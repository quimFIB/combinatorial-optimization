07

Branch and bound

Split the problem, bound each piece with an LP, and throw away every piece that cannot win. What to split on and which piece to look at next decide everything.

needs 05~2 h slides + 3 h lablab: uv run co lab 07

Branch and bound (Land & Doig, 1960) is the skeleton of every MILP solver. Cutting planes (08), primal heuristics, presolve, conflict analysis and parallelism are all additions to this tree. The lab builds the skeleton and measures it against SCIP and HiGHS. The gap in node counts is what the next units explain.

Convention throughout: minimization. LP bounds are lower bounds, and the incumbent (best integer solution found) is an upper bound.

How to read this deck

One two-variable integer program, small enough to draw, runs through the unit. Its tree, both node orders, and the branching scores were all computed with the lab's reference solution, so you can reproduce every number. The big tables come from then.

section 1

The tree

Divide the feasible set, and conquer only the pieces that could still contain the optimum.

07 · tree · example

The running example

Dots: the 7 integer points. Ring: the root LP optimum. Branching on $y$ keeps the strip $y \le 2$ and the empty region $y \ge 3$; the gap between the dashed lines holds no integer point.

$$\begin{aligned}\min\ & -x - 5y \\ \text{s.t. } & 7x + 3y \le 22 \\ & -3x + 3y \le 2 \\ & x, y \ge 0 \text{ integer}\end{aligned}$$

Minimizing $-x - 5y$ means maximizing $x + 5y$: $y$ is worth five times as much.

what the root LP says

Dropping integrality, the optimum is the corner $(2, \tfrac83)$ with value $-\tfrac{46}{3} = -15.33$. That is a lower bound: no integer point does better.

$y = 2.67$ is fractional, so branch on it: $y \le 2$ or $y \ge 3$. The next slide is the whole tree.

The polygon. Corners $(0, 0)$, $(\tfrac{22}{7}, 0)$, $(2, \tfrac83)$ and $(0, \tfrac23)$. The top corner is where $7x + 3y = 22$ meets $y = x + \tfrac23$: substituting, $10x + 2 = 22$, so $x = 2$, $y = \tfrac83$.

The integer points. $(0,0), (1,0), (2,0), (3,0), (1,1), (2,1), (2,2)$. Their values of $x + 5y$ are 0, 1, 2, 3, 6, 7, 12, so the optimum is $(2, 2)$ with objective $-12$. Checking $(2,2)$: $14 + 6 = 20 \le 22$ and $-6 + 6 = 0 \le 2$. Nothing with $y = 3$ fits: $y \le x + \tfrac23$ needs $x \ge 3$, and then $7x + 3y \ge 30 > 22$.

In code this is a MILP with c = (-1, -5), A_ub = ((7, 3), (-3, 3)), b_ub = (22, 2), both variables integer in $[0, 10]$. The reference branch_and_bound with most-fractional branching solves it in 5 nodes best-first and 9 depth-first.

07 · tree

LP-based branch and bound

  1. Solve the root LP. If its solution is integral, done.
  2. Otherwise pick a fractional $x_j = v$ and create two children (branching): $x_j \le \lfloor v \rfloor$ and $x_j \ge \lceil v \rceil$. Every integer solution is in exactly one child.
  3. Solve each child's LP, and repeat on the open nodes.
prune a node when
  • its LP is infeasible ($y \ge 3$);
  • its LP is integral: it becomes the incumbent if better ($(2,2)$);
  • its LP bound is $\ge$ the incumbent: nothing below it can win ($x \ge 3$).

explore interactively

Correctness in two lines. The children partition the parent's integer feasible points: no integer satisfies $\lfloor v \rfloor < x_j < \lceil v \rceil$. And each child's LP bound is a valid lower bound on every integer point in it. So pruning never discards a better solution, and the search is finite because bounded integer variables can only be tightened finitely often.

The fractional point itself is cut off in both children ($x_j = v$ violates both new bounds), so the same LP solution never repeats. That is why branching on a fractional variable makes progress, where branching on an integral one wouldn't.

The tree, node by node, from the reference solution. Root: LP $(2, \tfrac83)$, value $-\tfrac{46}{3}$; $y$ is the only fractional variable. Child $y \ge 3$: no point of the polygon has $y \ge 3$ (its top is $\tfrac83$), so the LP is infeasible. Child $y \le 2$: the LP moves right along $y = 2$ to $7x + 6 = 22$, $x = \tfrac{16}{7} = 2.29$, value $-\tfrac{86}{7} = -12.29$. Branch on $x$. Grandchild $x \le 2$: the LP optimum is $(2, 2)$, integral, value $-12$: the incumbent. Grandchild $x \ge 3$: $7 \cdot 3 + 3y \le 22$ gives $y \le \tfrac13$, optimum $(3, \tfrac13)$, value $-\tfrac{14}{3} = -4.67$, which is worse than $-12$, so pruned by bound. Five nodes, and $-12$ is proved optimal.

07 · tree

Two bounds, one gap

Upper bound $U$: the incumbent's objective value, or $+\infty$ before one is found.

Lower bound $L$: the smallest LP bound among open nodes. Every unexplored integer point lies in some open node.

$$L \le z^* \le U, \qquad \text{gap} = \frac{U - L}{|U|}$$

On the example, after the root and its two children: $U = +\infty$, $L = -12.29$. After $(2,2)$ is found: $U = -12$, and the only open node has bound $-4.67 \ge U$, so $L$ jumps to $-12$ and the gap closes to 0.

The solver stops when the gap is 0, or below a tolerance (HiGHS and Gurobi default to a relative gap of $10^{-4}$; SCIP to 0).

two hard jobs

Push $U$ down: find good integer solutions early, so pruning by bound starts early.

Push $L$ up: branch and cut so the open nodes' bounds rise toward $z^*$.

Everything in a MILP solver serves one of these two. A solver log is two columns, "primal bound" and "dual bound", converging.

Default gap tolerances are one reason a solver's "optimal" can differ slightly from the true optimum. A relative gap of $10^{-4}$ on an objective of $10^6$ allows 100 units of difference. Unit 05's tests use a gap of 0 when comparing solvers for exactly this reason, and the lab's own tree runs to a zero gap.

An instance can be "solved" in two senses. The primal side is having a solution, which is often all a practitioner needs. The dual side is having proved it optimal, which can take orders of magnitude longer. For many real models, most of the run time is spent raising $L$ after the eventual optimal solution was already found.

section 2

Node selection

Which open node to look at next.

07 · selection

Depth-first against best-first

depth-first

Always a child of the last node. Reaches integral leaves quickly, so an incumbent exists early. Small memory. It can spend a long time in a bad subtree.

best-first

Always the open node with the smallest bound. That raises $L$ as fast as possible. The frontier can grow huge, and incumbents come late.

why best-first uses fewest nodes

A node whose bound is below the optimum can never be pruned, so every search must branch on it. Best-first branches on those nodes and (up to ties) nothing else.

full argument in the notes (N)

What solvers ship: hybrids of node selection. Dive depth-first from a promising node to find a solution, then jump back to a node with a good bound or a good estimate (best estimate), with periodic plunges.

Full argument

Take any node $N$ with LP bound strictly below $z^*$. No incumbent can ever have value below $z^*$, so $N$ is never pruned by bound. It must be branched on unless its LP is integral, which is impossible because its value would then be below $z^*$. Conversely, best-first only pops nodes in bound order. Once the optimal solution has been found, every remaining node has bound at least $z^*$ and is pruned. Lab step 2's extra test checks this directly: the bounds of branched nodes come out nondecreasing and never above the optimum.

DFS's weakness in the numbers: on knapsack #0 it needed 5.5× the nodes. Its strength doesn't show in node counts, because the lab has no time limit. Under a time limit, DFS usually has a much better incumbent to report when time runs out.

"Nodes" counts every LP solved: the root plus every child created. Best-first creates the root, $y \le 2$, $y \ge 3$ (infeasible), $x \le 2$, $x \ge 3$: five. Depth-first's first incumbent, $-3$, is poor, but it would be a usable answer if time ran out. Best-first has nothing to report until its third pop. That is the trade-off of the previous slide in four rows.

section 3

Branching

Which variable to split on. The single biggest influence on tree size.

07 · branching

Most fractional, and why it's weak

Most-fractional branching. Intuition: a variable at 0.5 is "most undecided" (its fractionality is largest), so decide it.

Measured: about as good as branching on a random fractional variable (Achterberg, Koch & Martin 2005, on MIPLIB).

Fractionality says nothing about how much the bound will move. A variable at 0.5 with a zero-cost column changes nothing when fixed, while a variable at 0.9 on a tight constraint can end the subtree.

what a good rule estimates

For each candidate $j$, the bound improvements $\Delta_j^-$ and $\Delta_j^+$ of the two children, combined with the product score

$$\text{score}_j = \max(\Delta_j^-, \varepsilon) \cdot \max(\Delta_j^+, \varepsilon)$$

A product rewards moving both children, and a zero on one side isn't fatal because of the $\varepsilon$.

Why the product: the tree size is roughly driven by the worse of the two children. Branching that improves one child hugely and the other not at all barely helps, since the unimproved child is essentially the parent again. The older "linear" score $(1-\mu)\min + \mu\max$ with small $\mu$ captures the same intuition; Achterberg's experiments found the product consistently better.

The $\varepsilon$ matters: without it, a variable with a zero gain on one side scores 0 no matter how large the other side is, and many variables tie at 0 early in the search. Lab step 3's test checks that.

07 · branching

Strong branching and pseudocosts

strong branching

Compute $\Delta^\pm_j$ exactly: solve both child LPs for each candidate, then branch on the best. The best node counts known, and the most LP solves by far.

Lab totals, best-first: 1 271 nodes but 4 641 LP solves, 3.2 s, against most-fractional's 1 923 nodes and 1.3 s.

pseudocost branching

Estimate $\Delta^\pm_j$ from history: the average gain per unit of fractionality seen when branching on $x_j$ before, times the current fractionality. Costs nothing per node.

Weak at the top of the tree, where there's no history yet. Lab totals: 1 581 nodes, barely better than most-fractional.

reliability branching (Achterberg, Koch & Martin 2005)

Use strong branching on a variable until its pseudocosts are reliable (a few observations each way), then trust the pseudocosts. This is the default rule in SCIP, and the node count of strong branching at roughly the cost of pseudocosts.

The curriculum's checkpoint is the strong-branching trade-off. Strong branching wins on nodes because every branching decision is informed by exact child bounds. It loses on time because each node costs up to $2k + 1$ LP solves ($k$ candidates) instead of 1. In the lab, 3.7 LP solves per node on average. Whether it pays depends on how expensive an LP is compared with a node's other work, and on how much it shrinks the tree.

Real strong branching is cheaper than the lab's. Solvers limit the dual simplex iterations per probe (a partial solve gives a lower bound on the gain), probe only the most promising candidates, and reuse the parent's basis as a warm start (unit 03).

Pseudocost initialization is the whole problem with pseudocosts. The lab uses the average of what has been seen, or 1.0, for unseen variables, which is uninformative, and that is why pseudocosts barely beat most-fractional here. Reliability branching exists to fix exactly this.

Exact values. Node $y \le 2$ has bound $-\tfrac{86}{7}$. Its children have $-12$ and $-\tfrac{14}{3}$, so $\Delta^- = \tfrac27$ and $\Delta^+ = \tfrac{160}{21}$, and the product is $\tfrac{320}{147} \approx 2.18$.

Pseudocosts divide a gain by how far the variable had to move. At the root $y = \tfrac83$ moves down by $\tfrac23$, gain $-\tfrac{86}{7} + \tfrac{46}{3} = \tfrac{64}{21}$, per unit $\tfrac{32}{7} = 4.57$. At node $y \le 2$, $x = \tfrac{16}{7}$ moves down by $\tfrac27$ (gain $\tfrac27$, per unit 1) and up by $\tfrac57$ (gain $\tfrac{160}{21}$, per unit $\tfrac{32}{3} = 10.67$). These are exactly the lists the reference tree stores in stats["pseudo"].

Candidates A and B are made up to show the two scores disagreeing; A is the kind of variable that makes one child much better and leaves the other essentially the parent.

section 4

The other job, and the gap to SCIP

Finding good solutions early, and what else solvers do.

07 · primal side

Primal heuristics

A good incumbent early lets bound pruning start early. Solvers spend a share of their time on primal heuristics that find one:

  • Rounding: round the LP solution in a way that keeps feasibility where possible (simple rounding, ZI rounding).
  • Diving: fix a variable, re-solve the LP, repeat, down one branch without keeping the tree.
  • RINS (Danna, Rothberg & Le Pape 2005): fix the variables where the incumbent and the LP agree, and solve the small sub-MILP that remains.
  • Feasibility pump (Fischetti, Glover & Lodi 2005): alternate between the LP polytope and the nearest integer point.
in the lab's tree

No heuristics: incumbents only come from integral LP leaves. That is one reason the DFS runs in then are so much larger than SCIP's. SCIP typically has a near-optimal solution before its tree has a dozen nodes.

On the running example, rounding the root LP $(2, 2.67)$ down gives $(2, 2)$, the optimum, before any branching.

Unit 26's local search and unit 19's LNS are the same idea used as stand-alone methods.

RINS is worth singling out, because it is a template that appears again in unit 19. It defines a neighbourhood from the disagreement between two solutions, a relaxed one and an integer one, and searches it exactly with the solver itself. That is large neighbourhood search with a MILP as the repair operator.

Heuristics are also run at nodes deeper in the tree, with their frequency tuned so that their cost doesn't dominate. SCIP's log shows which heuristic found each improving solution. Reading that column is part of the then assignment.

hypotheses to test
  • Cutting planes raise the root bound (unit 08). Default vs bare SCIP isolates them plus presolve.
  • Presolve tightens bounds and coefficients (units 05, 27).
  • Branching: reliability branching vs yours. Bare SCIP still wins by 2–5×.
  • Heuristics give an early incumbent, and more pruning.
  • Conflict analysis learns from infeasible nodes (the SAT idea of unit 20).

The two columns for SCIP separate the effects roughly. Going from yours to SCIP bare shows the effect of better branching and better LP handling. Going from SCIP bare to SCIP default shows the effect of cuts, presolve and heuristics. On the facility-location model almost the whole gap is in the second column, which is unit 05's lesson again: the solver repairs the weak formulation.

The curriculum asks you to write your hypotheses down now and test them in units 08 and 27. Writing them before reading on is the point.
