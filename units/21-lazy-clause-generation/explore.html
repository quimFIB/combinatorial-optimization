The order encoding, and one precedence

Try: decide x ≥ 2 and read the explanation clause; then pull y ≤ 4 and get a conflict. Static versions: the order encoding, explanations.

What it shows. x + 3 ≤ y with x ∈ 0..3 and y ∈ 0..6, in the order encoding. The sliders are decisions (a lower bound on x, an upper bound on y). The figure shows the bounds that remain, every explanation clause the precedence handed to CDCL, and the staircase of literals [x ≤ v], [y ≤ v].

At the root the precedence already explains y ≥ 3 with the one-literal clause ¬[y≤2]; deciding x ≥ 2 adds ([x≤1] ∨ ¬[y≤4]), the deck's clause.

Data. slides/viz/traces/u21.py runs the reference Model, IntVar, Precedence and LCGSolver for all 28 slider positions.

A learned clause mixing a Boolean and a bound

Try: step to the explanation that is already false, then the analysis, which learns (¬b ∨ [a≤1]). Static version: Explanations, on one precedence.

What it shows. Unit 20's CDCL stepper on a lazy clause generation run: two tasks of length 3 on one machine, starts a, c ∈ 0..4, and a Boolean b for "a before c". Deciding a ≥ 2 (that is, ¬[a≤1]) and then b makes the enabled precedence explain itself with a clause whose literals are all false: a conflict, learned as (¬b ∨ [a≤1]), backjump to level 1, where ¬b follows.

Data. slides/viz/traces/u21.py wraps the reference LCGSolver in unit 20's recorder; the first two decisions are scripted to follow the deck.
