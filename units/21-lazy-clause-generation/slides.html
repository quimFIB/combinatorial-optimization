Lazy clause generation, or what CP-SAT actually is

Propagators that explain themselves as clauses, a CDCL engine that learns from them, and a linear relaxation running alongside: the hybrid that ate the field.

needs 19, 20~1½ h slides + 2½ h lablab: uv run co lab 21

Lazy clause generation was developed at the University of Melbourne (Ohrimenko, Stuckey & Codish 2007–09) and quickly dominated the MiniZinc Challenge. Google's CP-SAT is built on the same idea, with a linear relaxation and a portfolio of LNS workers added. It has taken most of the MiniZinc Challenge's gold medals since 2018.

The unit is short because it assembles pieces you already have: unit 18's propagators, unit 20's CDCL, unit 19's LNS, Part II's LP. The one new idea is the explanation.

How to read this deck

Two example slides make the new idea concrete: the order encoding of a variable with four values, written out in full, and a precedence $x + 3 \le y$ whose propagations come with their explanation clauses, ending in a learned clause that mixes a Boolean with a bound. Every clause was produced by the lab's reference solution.

Integers as Booleans: the order encoding

The order encoding: for $x \in [\ell, u]$, one Boolean (a bound literal) per threshold:

$$[x \le \ell],\ [x \le \ell + 1],\ \dots,\ [x \le u - 1]$$ $$[x \le v] \rightarrow [x \le v + 1]$$
  • A bound change is a single literal: $x \ge 5$ is $\lnot[x \le 4]$.
  • Each integer value corresponds to exactly one Boolean assignment (lab step 1's test: 6 models for $x \in 0..5$).
  • Variables are created lazily in real solvers, only for thresholds propagation actually uses.
other encodings

Direct $[x = v]$: good for ≠ and tables, and bad for bounds. Log (binary digits): compact, and propagation is weak. The order encoding is what makes bounds reasoning into unit propagation. It's the right choice for scheduling and arithmetic, and LCG solvers often keep both $[x \le v]$ and $[x = v]$, linked by clauses.

Tamura et al.'s Sugar (2009) showed the order encoding makes pure SAT competitive on scheduling. LCG keeps the encoding and removes the need to write out the constraints.

The size problem the order encoding creates: a domain of size 10⁶ needs 10⁶ Booleans if created eagerly. That's why LCG solvers create $[x \le v]$ literals on demand, and why CP-SAT represents integer bounds natively and creates Boolean views only when an explanation or a branch needs one. The lab creates them eagerly for simplicity. On ft06 with horizon 60 that's about 2 000 Booleans.

The order encoding, on four values

$x \in \{0, 1, 2, 3\}$: three literals $[x \le 0]$, $[x \le 1]$, $[x \le 2]$, and two clauses

$\lnot[x \le 0] \lor [x \le 1], \qquad \lnot[x \le 1] \lor [x \le 2]$

$x$$[x \le 0]$$[x \le 1]$$[x \le 2]$
0truetruetrue
1falsetruetrue
2falsefalsetrue
3falsefalsefalse

Of the $2^3 = 8$ assignments, the two clauses allow exactly these 4: one per value.

bounds become single literals

$x \ge 2$ is $\lnot[x \le 1]$: set $[x \le 1]$ false. Unit propagation on the first clause then makes $[x \le 0]$ false too: $x \ge 1$ follows for free.

$x \le 2$ is $[x \le 2]$ itself. Both together leave only the row $x = 2$.

A domain with a hole, $x \ne 1$, is not one literal here: that is what the direct encoding's $[x = 1]$ is for.

explore interactively

The reference IntVar(model, 0, 3) creates exactly three Boolean variables and the two implication clauses above. Enumerating all eight assignments against those clauses leaves four, the rows of the table: the literals read as a "staircase", false up to the value and true from it on.

The propagation in the box: setting $[x \le 1]$ false makes the clause $\lnot[x \le 0] \lor [x \le 1]$ unit on $\lnot[x \le 0]$. Bounds reasoning in the integer view ("$x \ge 2$ implies $x \ge 1$") is unit propagation in the Boolean view, which is the whole reason the encoding is chosen.

A propagator's inference, as a clause

A propagator narrows a bound. LCG requires it to also return an explanation: a clause

  • that holds in every solution of the constraint (so it can be kept forever),
  • whose literals are all false now except the new one (so it propagates it).
precedence $$\begin{aligned} & [x \ge a] \rightarrow [y \ge a + d] \\ \equiv\ & \lnot[x \ge a] \lor [y \ge a + d] \end{aligned}$$
unary resource, and one task's compulsory part

Task $i$ surely runs during $[lst, ect)$ (latest start, earliest completion), so task $j$ can't overlap it:

$[s_i \le lst] \land [s_i \ge ect - d_i] \land [s_j \ge lst - d_j + 1] \rightarrow [s_j \ge ect]$

CDCL treats explanation clauses exactly like input clauses (an explained propagator is just a clause source): as reasons in the implication graph. Conflict analysis resolves through them, and a learned clause mixes Boolean decisions with integer bounds, in this shape:

¬[s₃ ≥ 12] ∨ ¬b₃,₇ ∨ [makespan ≥ 58]

"If operation 3 starts at 12 or later and precedes operation 7 on their machine, the makespan is at least 58." A nogood like that would take unit 17's engine an entire subtree to rediscover, every time.

Lab steps 2–3's tests decode every returned clause back to integers and check it against every feasible assignment.

Explanation quality matters. The most general explanation (fewest, weakest literals) produces learned clauses that prune the most. The lab's timetable explanation uses the bounds that justify the compulsory part, not the current bounds. A lazy implementation that explains with "all current bounds of all tasks" would be valid but would learn clauses that almost never fire again.

That's also why explanations are generated lazily in real solvers (lazy explanation): a propagator records only enough to reconstruct the explanation, and builds the clause only if conflict analysis actually resolves through that literal. Most propagated literals never are.

Explanations, on one precedence

$x + 3 \le y$ with $x \in 0..3$, $y \in 0..6$.

momentpropagationexplanation clause
root$y \ge 3$$[y \ge 3]$ alone: true in every solution, since $x \ge 0$
decide $x \ge 2$$y \ge 5$$\lnot[x \ge 2] \lor [y \ge 5]$

In order-encoding literals the second clause is $[x \le 1] \lor \lnot[y \le 4]$. It mentions only $x$'s bound that caused the push, not the decision's history, so it is valid forever and can be learned from.

a learned clause mixing a Boolean and a bound

Two tasks of length 3, starts $a, c \in 0..4$, on one machine. A Boolean $b$ picks the order: $b \Rightarrow a + 3 \le c$, and $\lnot b \Rightarrow c + 3 \le a$.

Level 1: decide $a \ge 2$. Level 2: decide $b$. The precedence needs $c \ge 5$, but $c \le 4$: its explanation $\lnot b \lor \lnot[a \ge 2]$ is all false, a conflict.

Learned: $\lnot b \lor [a \le 1]$, "if $a$ starts at 2 or later, $a$ can't go first". Backjump to level 1, where it forces $\lnot b$.

explore interactively

The table is the reference Precedence.propagate. At the root, $x$'s lower bound is its initial bound 0, so the reason part of the clause is empty and the clause is just the new literal $[y \ge 3] = \lnot[y \le 2]$. After enqueuing $\lnot[x \le 1]$ at level 1, the propagator returns $[x \le 1] \lor \lnot[y \le 4]$, and after unit propagation $y$'s bounds are $[5, 6]$.

The learned clause is from a traced LCGSolver: decide $\lnot[a \le 1]$ (level 1; unit propagation also sets $\lnot[a \le 0]$), decide $b$ (level 2). The enabled precedence computes $a_{lo} + 3 = 5 > c$'s upper bound 4, so its clause has no head literal and is entirely false. First-UIP analysis stops at once (one level-2 literal, $\lnot b$) and returns $\lnot b \lor [a \le 1]$ with backjump level 1 and LBD 2. On a real job-shop, the same kind of clause relates an order Boolean to start-time bounds, and it prunes every subtree that repeats that combination.

Measured: what learning from propagation buys

instanceunit 18 CPLCG

Ablation on ft06:

variantconflictss
disjunctions + explained timetable1543.8
disjunctions only2865.2
no restarts1543.7

Stronger propagation halves the proof. Learning turns an unfinished search into a proof. It is not a constant factor: nogoods cut every symmetric and repeated subtree the CP search would re-enter.

Why the effect is so large on job-shop in particular. The same critical overlaps recur in thousands of subtrees that differ only in irrelevant decisions on other machines. A CP search without memory proves each of those subtrees infeasible separately. A learned clause names only the literals involved in the overlap, so it prunes all of them at once. That's the same phenomenon as unit 17's 3-colouring comparison, now inside your own code.

The same idea, elsewhere

A theory explains; a SAT solver learns.

21 · elsewhere

SMT, DPLL(T), and logic-based Benders

DPLL(T) (Nieuwenhuis, Oliveras & Tinelli 2006)

A CDCL solver over Boolean abstractions of theory atoms ($x - y \le 3$, $f(a) = b$). A theory solver checks the current atoms for consistency and returns a theory explanation (a clause) on conflict or propagation. Z3, CVC5 and Yices work this way.

LCG is DPLL(T) with CP propagators as the theory, arriving from the CP side. SMT is the same idea arriving from verification.

logic-based Benders (Hooker & Ottosson 2003)

Unit 12's Benders with any subproblem solver: the subproblem returns an inference, a no-good or bound cut, about the master's decision. Same shape: one solver decides, another explains, and the first learns.

the common pattern

Decide, check, explain: decide in one representation. Check or propagate in a richer one. Hand back a certificate of why in the first representation. Units 09 (separation), 10 (pricing), 12 (Benders cuts) and 21 are all this pattern.

The difference between DPLL(T) and LCG is mostly engineering emphasis. SMT theories are often expensive and incremental (the simplex method for linear arithmetic, congruence closure for equality). CP propagators are many, cheap, and specialised to one global constraint each. Both depend on explanations being small.

Reading CP-SAT's log

Lab then, 15×15 job-shop, 5 s, 8 workers (352 log lines):

log sectionwhat it isbuilt in

Lp stats, Lp CutLP relaxation; CG, MIR, no-overlap cuts02–08
LNS statsgraph_*, rnd_*, scheduling_* neighbourhoods19
  • CP-SAT's LCG core: integer variables with lazily created literals, and propagators (no-overlap, cumulative, linear) that explain.
  • LP relaxation in some workers (LP workers) (max_lp, reduced_costs), cutting planes included, used for bounds and reduced-cost fixing (unit 11's idea).
  • Portfolio: different workers with different heuristics, restart policies and LP levels, sharing incumbents (a shared incumbent), bounds and (optionally) clauses.
  • LNS workers improving the incumbent: unit 19 at industrial scale.

Makespan 1211 against a bound of 1162 after 5 s: not proven, which is typical for 15×15 job-shops.

Reading the log is a skill worth practising on your own models. When CP-SAT is slow, the log usually says why. The LP workers' bound may not move, meaning a weak relaxation (reformulate, unit 05). Search workers may have many conflicts but no incumbent (add hints, or check the model for symmetry). LNS may improve the incumbent while the bound is stuck, meaning the proof is the hard part, not finding solutions.

MIP, CP, SAT, or CP-SAT?

if the problem has…reach first forbecause
a strong LP relaxation (flows, covering, assignment with costs)MIPthe bound does the proving (Part II)
big-M disjunctions, scheduling, sequencingCP-SATno-overlap propagation + learning beats weak big-M LPs (units 05, 18, 21)
pure feasibility, Boolean structure, verificationSATCDCL, proofs, and preprocessing (unit 20)
huge instances, need good solutions not proofsCP-SAT LNS, or a metaheuristicunit 19; unit 26
counting / cardinality at the core (pigeonhole-like)MIP or a global constraint, not plain SATresolution can't count (unit 20)
nonlinear continuous partsMINLP / a spatial B&B solveroutside this course's solvers
the three questions
  1. What does the LP relaxation see? If its bound is close to the optimum, MIP proves quickly.
  2. What does propagation see? If the constraints are global and combinatorial, CP propagators prune early.
  3. What can learning reuse? If the same local conflicts recur across the search, nogoods pay off.

Then measure, on several instances (unit 28). CP-SAT's portfolio is an admission that nobody can answer these questions in advance for every instance.

A worked example of the checkpoint. Nurse rostering (shifts, coverage per day, rest rules, fairness): the coverage constraints are LP-friendly, but the rest rules are sequence patterns (regular constraints) and big-M-hostile, and fairness is a min-max. The first reach is CP-SAT: native sequence and linear constraints, learning for recurring rule conflicts, and an LP worker for the coverage bound. MIP would be a reasonable second, with a column-generation formulation (unit 10) if the instances are large.

A note on proofs. Unit 20's DRAT proofs don't carry over directly: an explanation clause is not implied by the CNF (it follows from the integer constraint), so a RUP checker rejects it. Certifying LCG needs proof formats that can justify theory lemmas, such as VeriPB for cutting-planes reasoning. That's an active research area.
