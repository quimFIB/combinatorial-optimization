* Step 1 — 3-SAT to vertex cover

** Rung 1 — the edges
Collect them in a set of ~(min, max)~ pairs, then ~tuple(sorted(...))~. For clause j, write
~corners = [2n + 3j + t for t in range(3)]~. Add the three triangle edges, then for each t the edge
between ~corners[t]~ and ~literal_vertex(clause[t])~.

** Rung 2 — why k = n + 2m works
Any cover needs at least one vertex of each variable edge (n) and two corners of each triangle (2m),
so every cover has at least k vertices. A cover of exactly k has one vertex per variable and two corners
per triangle. The uncovered corner's link edge must then be covered by its literal's vertex, so that
literal is chosen, which means true. Every clause has a true literal.

** Rung 3 — both maps
Forward: cover the true literal of each variable, and in each clause all corners except one whose
literal is true. Backward: x_v is true iff vertex 2(v−1) is in the cover. The tests map a /minimum/
cover back, which has size k exactly when the formula is satisfiable.

** Functional route
Three lists concatenated then ~tuple(sorted(set(...)))~: variable edges, triangle edges
~for j ... for a, b in ((0, 1), (0, 2), (1, 2))~, and links ~for j, c in enumerate(clauses) for t, lit in enumerate(c)~.
The forward map is a set of literal vertices united with a set of corners, using
~for keep in [next(...)]~ inside the comprehension to name the kept corner.

* Step 2 — Clause splitting

** Rung 1 — the chain
For (l₁ … l_k) with k > 3, the fresh y₁ … y_{k−3} mean "the clause is still unsatisfied by the
literals so far", read in the direction the clauses force. The first clause (l₁, l₂, y₁) forces
y₁ if l₁ and l₂ are false. The last (¬y_{k−3}, l_{k−1}, l_k) demands one of the last two when the
chain arrives true.

** Rung 2 — extending an assignment
Set y_i = True iff none of l₁ … l_{i+1} is true. Check: clause (¬y_{i−1}, l_{i+1}, y_i) is satisfied
because either some earlier literal was true (y_{i−1} false) or l_{i+1} is true (then y_i can stay
false), or neither (then y_i is true). Because the original clause is satisfied, the last clause is
too.

** Functional route
Write ~_split(clause, top)~ returning ~(new clauses, fresh variables used)~, then fold:
~tz.reduce(lambda st, c: (st[0] + used, st[1] + new), clauses, (nvars, []))~. Extension is
~assignment + concat(fresh_values(c) for c in clauses)~, with
~[not any(truth[:i + 2]) for i in range(k - 3)]~ for a long clause.

* Step 3 — Vertex cover to set cover

** Rung 1
~frozenset(e for e, (a, b) in enumerate(vc.edges) if v in (a, b))~ for each v. The universe is
~len(vc.edges)~. Solutions and objective values are identical, so optimality is preserved, not just
feasibility. That is the property the tests (and ~then~) check.

** Functional route
A reduction is a pure function between instance types. Group the (vertex, edge index) incidences with
~tz.groupby(0, ...)~, and each vertex's set is the frozenset of its edge indices. Weights are all 1. Composing
with step 1 gives SAT → set cover, one line, and the solution maps compose the same way.

* Step 4 — The FPTAS

** Rung 1 — DP by value
~W = [0] + [inf] * sum(values)~. For each item, loop p downwards from the total to v: if
~W[p - v] + w < W[p]~, update and record the choice. The answer is the largest p with
~W[p] <= capacity~. Walk back through the items in reverse to recover them.

** Rung 2 — the guarantee
Rounding loses less than K per item, so less than nK = ε·vmax in total. Because every usable item
fits alone, OPT ≥ vmax, so the loss is at most ε·OPT. The table has at most n²/ε columns, giving
O(n³/ε) time. The tests include instances where dropping the "fits alone" filter, or scaling by
ε·vmax instead of ε·vmax/n, breaks it.

** Functional route
~itertools.accumulate(items, add_item, initial=(0,) + (inf,) * total)~ keeps one table per item;
each is a tuple comprehension over p. Recover items by iterating a ~back~ step from the last table:
item i−1 was taken iff ~tables[i][p] != tables[i - 1][p]~.
