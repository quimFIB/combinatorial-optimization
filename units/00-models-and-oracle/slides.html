Nothing here is deep. It is the unit you will use most. section 1

What makes a problem combinatorial

Finite, but only in the least useful sense of the word.

00 · definitions

Problems and instances

definition

An optimization problem is a set of instances. An instance is a pair $(F, c)$: a feasible set $F$ and an objective $c : F \to \mathbb{R}$. We want $x^* \in F$ with $c(x^*) \le c(x)$ for all $x \in F$ (or $\ge$, for maximization).

combinatorial

$F$ is finite, and given implicitly: a simple, enumerable space $S$ and constraints, $\;F = \{x \in S : x \text{ satisfies the constraints}\}$.

Example. Vertex cover: an instance is a graph $G=(V,E)$. The space is $S = \{0,1\}^V$, the constraints are $x_u + x_v \ge 1$ for every $uv \in E$, and the objective is $c(x) = \sum_v x_v$, to be minimized.

The distinction between problem and instance matters from the first complexity statement onward. "Vertex cover is NP-hard" is a claim about the problem, meaning all graphs. "This graph has a cover of size 12" is a claim about an instance. Running times are functions of the encoding size of an instance: the bits needed to write down the graph, the weights, the capacity.

Finite is what separates this from continuous optimization. Nothing here needs limits, derivatives or convergence arguments: in principle you can look at every element of $F$. Implicit is what makes that useless. $F$ is never handed to you as a list. You get a short description that generates an exponentially large set, and the whole subject is about reasoning over that set without listing it.

The formal definition is Papadimitriou & Steiglitz ch. 1. Korte & Vygen use the same idea with more machinery.

Finite, and astronomically so

Enumerating is always correct and almost always useless.

Almost always useless, but it is not worthless: for $n \lesssim 20$ it is the only solver whose correctness you can see by reading it.

scale

At a billion candidates a second, $2^{50}$ takes 13 days. $(50-1)!$ takes about $10^{46}$ years.

Check the arithmetic once, so the numbers feel real. $2^{50} \approx 1.13\times10^{15}$, and at $10^9$ per second that is $1.13\times10^6$ seconds, about 13 days. $49! \approx 6.08\times10^{62}$, so $6\times10^{53}$ seconds, or about $2\times10^{46}$ years. The universe is about $1.4\times10^{10}$ years old.

The course could be described as a list of reasons you do not have to enumerate:

  • structure that makes greedy exact (matroids, unit 13);
  • a continuous relaxation that is already integral (total unimodularity, 06);
  • bounds that prune most of the tree (branch and bound, 07);
  • propagation that removes values before search reaches them (CP, 17);
  • and, when none of these works, settling for a guaranteed approximation (Part V).

Your lab's then step measures where enumeration stops being possible on your own machine. Those numbers set the size of every small instance used in later tests.

00 · definitions

Four questions about one instance

versionasksvertex cover example
decisionis there $x \in F$ with $c(x) \le k$?is there a cover with at most 12 vertices?
evaluationwhat is $\min_{x\in F} c(x)$?the smallest cover has 11 vertices
search / optimizationfind an $x^*$ achieving ithere are the 11 vertices
countinghow many $x \in F$ have $c(x) \le k$?how many covers of size 11 exist?
fact

For integer objectives of polynomial bit size, the first three are polynomially equivalent. Counting can be much harder.

Decision to evaluation: the optimum lies in a range of integers whose width is exponential in the bit size, so binary search needs polynomially many calls to the decision version.

Evaluation to search: self-reducibility. For vertex cover, try deleting vertex $v$ and its edges and ask whether the optimum of the rest is one less. If it is, $v$ belongs to some optimal cover: commit to it and recurse. That is $|V|$ more evaluation calls.

Counting is a different world. Deciding whether a bipartite graph has a perfect matching takes polynomial time (unit 15). Counting perfect matchings is #P-complete (Valiant 1979), and so is computing the permanent of a 0/1 matrix. The course is almost entirely about decision and optimization; this is here so that "easy" is never assumed to mean "easy to count".

Complexity classes are defined on decision versions, which is why hardness statements are phrased as "is there a solution of value at most $k$?"

Things to notice already:

  • Assignment is the odd one out: it is solvable in polynomial time. It is on the list because it is the clearest case where the LP relaxation is already integral. Solving the LP solves the problem.
  • Knapsack and bin packing are both NP-hard, in different ways. Knapsack has a pseudo-polynomial DP, $O(nC)$, which is fast whenever the capacity $C$ is small. Bin packing stays NP-hard even when every number is small (strongly NP-hard). Unit 22 makes that precise.
  • Max-cut has no constraints. Every subset is feasible. All of the difficulty is in the objective, which is why it is the natural testbed for relaxations (unit 25).
  • Vertex cover is the one you will model yourself in the lab, and the one used for the certificate example below.

00 · the nine

One problem, three descriptions

As a predicate

what an oracle needs

def feasible(G, x):
    return all(x[u] or x[v]
               for u, v in G.edges)

def objective(G, x):
    return sum(x)

As an integer program

Parts I–II

$$\begin{aligned}\min\ & \textstyle\sum_{v} x_v \\ \text{s.t. } & x_u + x_v \ge 1 \quad \forall uv \in E \\ & x \in \{0,1\}^V\end{aligned}$$

As a constraint model

Part IV

x = [model.NewBoolVar(f"x{v}")
     for v in V]
for u, v in E:
    model.AddBoolOr(x[u], x[v])
model.Minimize(sum(x))

Same feasible set, three languages. What differs is what a solver can infer from the description without enumerating.

The predicate is a black box. The only thing you can do with it is evaluate it at a point, so enumeration is the only algorithm it admits. The integer program exposes linear structure: drop $x \in \{0,1\}$ to $0 \le x \le 1$ and you get an LP whose optimum is a lower bound. For vertex cover that LP has a surprising property (unit 24): some optimal solution uses only the values $0$, $\tfrac12$, $1$. The constraint model exposes logical structure: once $x_u$ is false, $x_v$ must be true, and a propagator can deduce that without search.

A theme to watch for: the same problem, written two ways that are logically equivalent, can differ in solve time by orders of magnitude. Unit 05 measures this for MIP formulations and unit 18 for global constraints.

The third block is OR-Tools CP-SAT syntax, shown only to recognize later. Nothing in this unit uses a solver.

00 · spaces

The space is a modelling choice

Bin packing, $n$ items. Two spaces, the same feasible packings:

spacesize$n = 10$
every map item → bin$n^n$10 000 000 000
set partitions$B_n$115 975

The first space counts every relabelling of the bins as a new packing. The second counts each packing once: 86 000× fewer.

restricted growth strings

$a_0 = 0,\quad a_i \le 1 + \max(a_0,\dots,a_{i-1})$

$a_i$ is item $i$'s bin. Bins are opened in order, so each partition of $\{0,\dots,n-1\}$ has exactly one string. For $n=3$:

000 001 010 011 012

This is symmetry breaking. Later it is the biggest single lever on real MIP and CP models (units 05, 27).

Why the strings work: read left to right, and give each new block the next unused label. Every partition has exactly one such canonical labelling, and every restricted growth string is canonical, so the map is a bijection with partitions. Counting them gives the Bell numbers $1, 1, 2, 5, 15, 52, 203, 877, 4140, 21147, 115975, \dots$

The same idea elsewhere: a TSP tour is a cyclic order, so fixing city 0 first cuts $n!$ to $(n-1)!$. For symmetric distances, identifying a tour with its reverse halves it again. Colouring has the same symmetry as bin packing, since colours are interchangeable.

Symmetry matters far beyond enumeration. A branch-and-bound solver on a symmetric model proves the same subtree infeasible once for every relabelling. Solvers detect and break symmetry automatically (orbital fixing, orbitopes), but a model that avoids it is still better. You will write the enumerator in lab step 2.

section 3

Certificates

"Here is the answer" and "here is why nothing is better" are different objects.

00 · certificates

Two kinds of evidence

upper bound · "at most k"

Exhibit $x \in F$ with $c(x) = k$.

Anyone checks it by evaluating the constraints and the objective. For all nine problems that takes polynomial time. This is exactly what puts the decision versions in NP.

lower bound · "at least k"

Show that no $x \in F$ has $c(x) < k$.

Enumeration proves it, but the proof is exponentially long. Is there a short proof? For NP-hard problems, in general, it is believed there is not: that is NP ≠ coNP.

Yet for particular instances, and for whole problem classes, short lower-bound proofs do exist. Finding them is most of the course.

For a minimization problem, a feasible solution gives an upper bound on the optimum, and it is its own certificate. A lower bound needs an argument about every solution at once.

In complexity terms, the decision question "is the optimum at most $k$?" has short, checkable "yes" certificates, which is NP. Short checkable "no" certificates would put it in coNP. If any NP-complete problem were in coNP, then NP = coNP, which is widely believed false. So no general short lower-bound certificate is expected for vertex cover.

That is a worst-case statement. On a given instance there is often a short proof, and the machinery of the course exists to find one:

  • LP duality (03): a dual solution is a lower-bound certificate for the LP.
  • Branch and bound (07): the search tree together with the LP bounds at its leaves is the certificate.
  • Cutting planes (08): the derivation of the cuts.
  • DRAT proofs (20): SAT solvers emit a checkable proof of unsatisfiability.

Linear programming is the example that matters most: it had short certificates in both directions, so it was known to be in NP ∩ coNP, years before Khachiyan (1979) showed it is in P. Unit 01 builds the "no" certificate for feasibility.

00 · certificates

A lower bound for vertex cover

lemma

If $M$ is a matching and $C$ a vertex cover in the same graph, then $|C| \ge |M|$.

proof

Each edge of $M$ needs an endpoint in $C$. The edges of $M$ share no endpoints, so those are $|M|$ distinct vertices. $\square$

So a cover and a matching of the same size prove each other optimal.

Filled vertices: a cover of size 2. Thick edges: a matching of size 2. Each proves the other optimal.

This is the first duality argument of the course, in miniature. Write $\nu(G)$ for the largest matching and $\tau(G)$ for the smallest cover. The lemma says $\nu(G) \le \tau(G)$ for every graph: weak duality. Any matching is a lower bound on any cover, just as, in unit 03, any dual feasible solution bounds any primal one.

The certificate is short (at most $|V|/2$ edges) and quick to check: are these edges of $G$, and are they disjoint? You will write the checker in lab step 4.

A second look at the proof: it only used that matched edges are disjoint and that each needs a cover vertex. That is the LP inequality $\sum_{uv \in M} (x_u + x_v) \ge |M|$ together with $\sum_v x_v \ge \sum_{uv\in M}(x_u+x_v)$, the second holding because $M$ is a matching. Adding up constraints with nonnegative weights to bound the objective is exactly what an LP dual does.

00 · certificates

When the bound is not enough

On a triangle, the largest matching has 1 edge, and the smallest cover needs 2 vertices. No matching certifies the optimum. The gap is real.

könig, 1931

In a bipartite graph, $\max |M| = \min |C|$. The certificate always exists.

The triangle is the smallest odd cycle, and odd cycles are exactly what bipartite graphs lack. That coincidence is where polyhedral combinatorics starts (units 06, 15).

Any edge is a maximum matching (1). Any two vertices form a minimum cover (2).

Can the gap be large? Not in ratio, and it is worth seeing why: the endpoints of a maximal matching always form a cover, so $\tau \le 2\nu$. The matching bound is never off by more than a factor of 2, and this is the 2-approximation for vertex cover in unit 23, which is this slide turned into an algorithm.

The fractional view (unit 24): relax both to LPs. The fractional vertex cover $x_v = \tfrac12$ on the triangle costs $\tfrac32$, and the fractional matching $y_e = \tfrac12$ has value $\tfrac32$. These two LPs are duals, so their optima coincide: $$\nu = 1 \;\le\; \nu^* = \tfrac32 = \tau^* \;\le\; \tau = 2.$$ All of the gap comes from integrality, not from duality. On bipartite graphs the constraint matrix is totally unimodular (unit 06), so the LPs have integral optima, and König's theorem follows from LP duality.

The lab's step 4 test runs your checker over every cover and every edge set of the triangle, and expects every certificate to be rejected.

section 4

An oracle you trust

Slow, obviously correct, and the reference every later lab is checked against.

00 · oracle

Brute force, done once and done right

def brute_force(problem):
    best = best_x = None
    feasible = examined = 0
    for x in problem.space():
        examined += 1
        if not problem.is_feasible(x):
            continue
        feasible += 1
        v = problem.objective(x)
        if best is None or better(v, best, problem.sense):
            best, best_x = v, x
    return Result(best, best_x, feasible, examined)

Obviously correct: it is the definition of the optimum, executed.

Self-certifying: examined == space.size() is the lower-bound proof.

Generic: one function for all nine problems, because every problem has the same interface.

Where people slip: initializing best to 0 or ∞ (wrong for one sense), and reporting a value on infeasible instances.

The value of an oracle comes entirely from being easy to believe. That rules out anything clever. No pruning, no early exit, no incremental evaluation: each of those is a new place for a bug to hide, and a buggy oracle is worse than none, because it teaches you to trust wrong answers.

The interface, space(), is_feasible, objective, sense, is what makes the oracle generic. Every problem in colib has it. When a later unit adds a problem, it gets an oracle for free.

Keeping both counts, feasible and examined, costs nothing and gives two sanity checks. examined must equal the size of the space. And feasible tells you how constrained an instance is: random set cover instances are mostly infeasible, max-cut instances are all feasible. That changes how informative a random test is.

00 · oracle

Differential testing

Smallest first. The first failure is the smallest counterexample the sweep contains, and so the easiest one to draw.

Feasibility checked separately. A "better than optimal" answer is always an infeasible one.

Ratio mode. For approximation algorithms, pass ratio=2 and check a guarantee, not equality.

This is property-based testing with a problem-specific property. The property is "agrees with the definition". If you have used Hypothesis or QuickCheck, the harness is a hand-rolled version, with instance generators in place of strategies and size ordering in place of shrinking.

Why smallest first instead of shrinking? For combinatorial instances a general shrinker is awkward to write (what is a smaller job-shop?), while sweeping sizes $1,2,3,\dots$ with many seeds is trivial and nearly as good. A failure at $n=6$ is a picture you can draw; a failure at $n=40$ is not.

Random instances have blind spots. They rarely produce the structured cases (complete bipartite graphs, instances with many ties, degenerate LPs) that break algorithms in practice. Later labs add hand-built instances next to the random sweep for this reason. Unit 28 treats instance selection as a methodological question in its own right.

The call is one line: differential(my_alg, instances(VertexCover, sizes=range(1, 13))).

00 · oracle

The harness catches what you believe

"Take the vertex covering the most uncovered edges."

On this spider it takes the centre (degree 3). The three leg-ends are then disjoint edges, and each costs one more vertex: 4.

The middle row covers everything with 3, and the three thick edges are a matching of size 3, so 3 is provably optimal.

No graph with fewer vertices makes max-degree greedy fail whatever the tie-breaking. In lab step 5 you write the heuristic, and the harness has to find a case like this on its own.

The counterexample was found by exhaustive search over all graphs with up to 7 vertices, looking for graphs where every tie-breaking choice of the greedy gives a suboptimal cover. There are none on 6 or fewer vertices; on 7, the spider with three legs of length 2 has the fewest edges. With a fixed tie-breaking rule, smaller failures exist, and the harness usually finds one around $n=6$.

The heuristic is not just occasionally wrong. There are bipartite families on which max-degree greedy is off by a factor of $\Theta(\log n)$, while the trivial "take both endpoints of an uncovered edge" rule is never worse than 2×. The more intuitive algorithm has the worse guarantee. Unit 23 has the construction.

Notice the slide uses both halves of this unit at once. The harness found that greedy is wrong; the matching certifies what right looks like, with no enumeration needed. On a graph of 1 000 vertices you could not run the oracle, but you could still check a matching.

rule for the rest of the course

Tests against brute force use $n \le 12$ for subset spaces, $n \le 8$ for tours and partitions. Anything larger needs a certificate or a trusted solver.

Your uv run co then 00 reproduces this table on your machine. Rewriting the oracle in C would buy about 100×. For $2^n$ that is $\log_2 100 \approx 6.6$ more items. For $(n-1)!$ it is barely one more city, since going from $n$ to $n+1$ already multiplies the work by $n$. Exponential walls do not move much for constant factors, and factorial ones move even less.

The test sizes in the box are chosen so that a full lab test run finishes in seconds, not minutes. Tests you have to wait for stop getting run.
