One rung at a time; then ~solution/lab.py~ or ~solution/functional.py~.

* Step 1 — The restricted master

** Rung 1
~A[i][p] = patterns[p][i]~, with shape (items, patterns). Then call
~highs_lp(A, np.full(m, np.inf), np.ones(P), sense="min", row_lower=np.array(demands, float))~.
Return ~info.value~, ~list(info.x)~ and the constraints' duals (~info.row_duals~).

** Rung 2 — dual signs
For a minimisation with ≥ constraints, the duals are ≥ 0. HiGHS can return −1e-17 for a zero,
so clip with ~max(0.0, y)~.

** Functional route
The initial patterns are one comprehension (~W // w~ in position i, zeros elsewhere). The master is a matrix
built by comprehension and one ~highs_lp~ call, and the duals are clipped at zero on the way out. An LP solve
is a pure function of its data, so there's no state here.

* Step 2 — Pricing

** Rung 1
~unit("16").unbounded_knapsack(duals, widths, W)~ returns ~(value, counts)~: values are
the duals, and weights are the widths. Return ~(value, tuple(counts))~.

** Rung 2 — Farley
Let v = max over patterns of a·y. Then y/v satisfies every dual constraint a·(y/v) ≤ 1,
so its objective d·y/v is a lower bound (weak duality). At the master's duals d·y is the
master value, so the bound is master / v.

** Functional route
Pricing delegates to unit 16's unbounded knapsack with the duals as values; wrap the counts in a tuple so
patterns are hashable. The Farley bound is one guarded expression.

* Step 3 — The loop

** Rung 1
#+begin_example
patterns = initial_patterns(...)
loop:
    value, x, duals = solve_master(patterns, demands)
    pv, pattern = price(W, widths, duals)
    best = max(best, farley_bound(demands, duals, pv))
    history.append((value, best))
    if 1 - pv >= -TOL: return value, patterns, x, history
    patterns.append(pattern)
#+end_example

** Functional route
~tz.iterate(step, start)~ where the state is a dict of patterns, value, x, best, history
and done. Take the first state with ~done~, bounded by ~tz.take(max_iter, ...)~.

* Step 4 — Integers

** Rung 1
~math.ceil(v - 1e-9)~ stops 3.0000000001 from rounding to 4. For the IP:
~MILP(c=(1,)*P, A_ub=-A, b_ub=-d, integer=(True,)*P)~, then ~highs_mip(...)~, then round
~res.x~.

** Functional route
Rounding up is a comprehension with ~math.ceil(v − 1e-9)~. The restricted master IP is an immutable ~MILP~
built from the patterns (covering constraints negated into ≤ form) and one ~highs_mip~ call.

* Step 5 — Smoothing

** Rung 1 — the two pricing calls
If a centre exists and α > 0, price at ~sep = α·centre + (1−α)·duals~. Compute that
point's Farley bound. If it beats ~best~, it becomes the new centre. Then compute the
reduced cost of the pattern /at the master duals/: ~1 - pattern·duals~. If it's
negative, add the pattern and continue.

** Rung 2 — the fallback
Otherwise price at the master duals, exactly as in step 3. That call's bound can also
become the centre, and it always does on the first iteration. If it finds nothing
negative, you're optimal: the master duals are dual feasible.

** Rung 3 — why termination is only decided at the master duals
A smoothed point that finds no column proves nothing about the master's duals. Only
pricing at the master duals can certify that no negative reduced-cost column exists.

** Functional route
The same unfold as step 3, with a richer state dict: patterns, the stability centre and the best bound so far.
A step solves the master, prices at the smoothed duals, and either adds that pattern or falls back to pricing at
the master duals, which is the only place termination is decided. It returns ~dict(s, ...)~ with the fields that
changed.

* Step 6 — Routes

** Rung 1 — labels
Represent a label as ~(rc, load, visited_mask, last, route)~. Start with one label per
customer v: ~(dist[0][v] - duals[v], demand[v], 1 << v, v, (v,))~. Each label can close:
~rc + dist[last][0]~.

** Rung 2 — dominance
Keep ~buckets[v]~, the non-dominated labels ending at v. A new label L at w is dropped if
some O in ~buckets[w]~ has ~O.rc <= L.rc~, ~O.load <= L.load~ and ~O.visited ⊆ L.visited~
(~O.mask & L.mask == O.mask~). Otherwise remove from the bucket every label L dominates,
and add L. Extend only labels that are still in their bucket.

** Rung 3 — why the visited set matters
A cheap, light label that already visited customer 7 can't be extended to 7. A
dominated label that hasn't visited 7 might end in the best route. So dominance needs
the subset condition. The test with high duals and roomy vehicles catches its absence.

** Rung 4 — the LP
Build one constraint per customer 1..n with ~row_lower = b = 1~ (equality). The duals are free in
sign; pass ~[0.0] + list(row_duals)~ to espprc. Add the routes with rc < −1e-6 that
aren't already present, and stop when there are none.

** Functional route
ESPPRC is a fold over path lengths. The state is ~(kept labels per last vertex, frontier, finished routes)~,
each extension builds every candidate one step longer, and ~admit~ folds the candidates into ~kept~ with
~tz.assoc~: skip a dominated label, and drop the labels it dominates. The new frontier is the candidates that
survived. Visited sets are frozensets, so dominance is ~a[2] <= b[2]~ (subset). The CVRP bound is step 3's
unfold again, over the route list.
