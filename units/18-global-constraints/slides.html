Global constraints and their filtering algorithms

One constraint that sees the whole structure beats many that each see a pair. Matching filters alldifferent; compulsory parts filter cumulative; the price is paid per call.

needs 17, 15~1¼ h slides + 3 h lablab: uv run co lab 18

A global constraint is a constraint over an unbounded number of variables with a dedicated propagator. The idea that made CP competitive in scheduling and timetabling in the 1990s was not a better search engine. It was propagators that exploit the combinatorial structure of one constraint using algorithms from Part III: matching for alldifferent, flows for global cardinality, shortest paths for regular.

This unit is also where the course's traditions start trading. Unit 15's Hopcroft–Karp becomes the inner loop of a CP propagator. In unit 21 the same propagators will explain themselves to a SAT solver.

section 1

Why global

Pairs cannot count.

18 · why global

What pairwise ≠ cannot see

$$x_1, x_2 \in \{1, 2\}, \quad x_3 \in \{1, 2, 3\}, \quad x_4 \in \{2, 3, 4\}$$
  • Pairwise ≠ (arc consistent): no variable is fixed, so nothing is pruned.
  • alldifferent (generalised arc consistent): $\{x_1, x_2\}$ use up $\{1, 2\}$, so $x_3 = 3$, so $x_4 = 4$.

$\{x_1, x_2\}$ is a Hall set: $k$ variables whose domains together hold exactly $k$ values. By Hall's theorem (unit 15), alldifferent is satisfiable iff no set of variables has fewer values than members.

the general fact

Arc consistency on a decomposition is at most as strong as generalised arc consistency on the global constraint, and often strictly weaker. For alldifferent, pairwise AC equals GAC only in the trivial case of fixed variables.

the design question

A stronger propagator removes more and costs more per call. It wins only if the nodes saved outweigh the time per node. That trade-off is the only design question in CP, and lab then shows both outcomes.

This slide's example is lab step 2's test test_step2_not_the_decomposition: every pairwise propagator returns its input unchanged, and your alldifferent returns $\{1,2\}, \{1,2\}, \{3\}, \{4\}$.

Bessière et al. (2004) showed that enforcing GAC on some global constraints is NP-hard. For those, the choice is between a weaker polynomial propagator and decomposition, and "global" does not automatically mean "strongest".

alldifferent

Unit 15, doing load-bearing work.

18 · alldifferent

Régin 1994: matching-based filtering

Thick: a maximum matching. Dashed: edges in no maximum matching, removed. {x₁, x₂} ↔ {1, 2} is an alternating cycle, so those edges stay.

  1. Build the value graph and find a maximum matching (Hopcroft–Karp). If it doesn't cover every variable: fail.
  2. By Berge, an edge lies in some maximum matching iff it is matched, or on an even alternating cycle, or on an even alternating path from a free value.
  3. Orient matched edges value → variable and the rest variable → value. Cycles are SCCs, and paths are reachability to free values. Remove every other edge.

$O(m \sqrt n)$ for the matching and $O(m)$ for the rest. Incrementally, the old matching is repaired rather than recomputed.

Lab step 2's test: on 80 random instances, the kept values equal brute-force supports exactly.

Why the Hall set falls out of the same graph (lab's hall_set). A removed edge $(x, a)$ has $a$'s node unable to reach a free value, and $x$ outside $a$'s component. Everything reachable from $a$ is a closed set: its values are all matched to variables in it, and its variables' edges all lead back into it. So those variables have exactly as many values as members, and they include $a$. That's the explanation a propagator gives in unit 21.

Cheaper alternatives. Bounds consistency for alldifferent (Puget 1998; López-Ortiz et al. 2003) runs in $O(n \log n)$ using Hall intervals. It is what most solvers use by default on large domains, keeping Régin's GAC for small ones.

a Hall set, by name

Two decisions down Inkala's solution path, pairwise ≠ at its fixpoint: alldifferent on row 7 removes 2 from r7c1 (domain {2, 4, 5, 7}). The Hall set: r7c2, r7c4, r7c5, r7c6, whose domains hold only {2, 4, 7, 9}.

  • Queens: a Hall set rarely forms before a variable is fixed, so alldifferent saves 18% of nodes and costs a matching per call. Slower.
  • Sudoku: rows, columns and boxes create Hall sets constantly. 35× fewer nodes.
  • Pigeonhole: no perfect matching at the root. Pairwise ≠ can only discover this by enumeration.

Pigeonhole returns in unit 20, where it's the canonical hard instance for resolution-based SAT solvers. The same counting argument that alldifferent performs in one matching needs exponential-size resolution proofs. Global reasoning isn't just faster; some of it is impossible for weaker proof systems to replicate efficiently.

Scheduling

Tasks, resources, time.

18 · scheduling

Cumulative, and timetable filtering

Duration 3, start ∈ {2, 3}: whatever it chooses, the task runs during [3, 5). Lab test: with capacity 1, a second task of duration 3 loses starts 1–4.

$\text{cumulative}(s, d, r, C)$: tasks with start variables $s_i$, durations $d_i$ and demands $r_i$ never use more than $C$ at once.

  • Compulsory part of task $i$: $[\max s_i,\ \min s_i + d_i)$ when non-empty.
  • Profile: the sum of demands of compulsory parts at each time. Above $C$ means fail.
  • Filter: remove a start $t$ of task $i$ if it would overload a time where the others' compulsory parts already sit.

Disjunctive scheduling (one machine) is cumulative with $C = 1$ and every $r_i = 1$. Lab step 4's job-shop uses one per machine.

The own-compulsory-part subtraction in the filter rule (lab hint) is the usual first bug: a task that sees its own demand at its own compulsory times rejects every start value it has.

Timetable filtering is weak when tasks have wide time windows, because their compulsory parts are empty and it sees nothing. That is precisely the situation at the top of a job-shop search, and why lab then finds ft06's optimum but can't prove it.

18 · scheduling

Stronger scheduling reasoning

  • Edge-finding (Carlier & Pinson 1989; $O(n \log n)$ with Θ-trees, Vilím 2004): if a task can't finish before a set $\Omega$ of tasks all end, given their total duration, it must end last, which raises its start.
  • Not-first / not-last: a task cannot be scheduled first (or last) among a set.
  • Energetic reasoning: the minimum energy each task must spend inside an interval, compared with $C \times$ interval length.
  • Time-table edge-finding (Vilím 2011), combining profile and edge-finding.

CP-SAT's no-overlap runs edge-finding, not-first/not-last and precedence reasoning, all explained as clauses and learned from (unit 21).

Edge-finding in one sentence: for a set $\Omega$ of tasks with earliest start $\text{est}_\Omega$, latest completion $\text{lct}_\Omega$ and total duration $d_\Omega$, if adding task $i$ makes $\text{est}_{\Omega \cup \{i\}} + d_{\Omega \cup \{i\}} > \text{lct}_\Omega$, then $i$ must end after every task in $\Omega$. Θ-trees maintain those sums over all relevant $\Omega$ at once, in a balanced tree keyed by earliest start.

the pattern

Each strong filter is an algorithm from Parts I–III wearing a CP interface: matching (alldifferent), flow (gcc), DP over an automaton (regular), shortest paths and assignment bounds (circuit, the TSP relaxations of unit 09). Global constraints are where the traditions first cooperate.

Beldiceanu, Carlsson & Rampon's Global Constraint Catalog lists 400+ constraints with semantics, decompositions and filtering algorithms.

gcc by flow, in brief: a source-to-variable arc of capacity 1 per variable, variable-to-value arcs for each domain value, and value-to-sink arcs with lower bound $l_a$ and upper bound $u_a$. A feasible flow is a solution. Filtering is Régin's alldifferent argument generalised: an arc is kept iff it carries flow in some feasible flow, found by SCCs of the residual graph. Alldifferent is the special case $l_a = 0$, $u_a = 1$.
