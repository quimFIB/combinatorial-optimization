* Step 1 — The barrier

** Rung 1
~s = b - A @ x~; if ~np.any(s <= 0)~, return ~(math.inf, None, None)~.
The Hessian without forming a diagonal matrix: ~A.T @ ((1 / s**2)[:, None] * A)~.

** Rung 2 — signs
d/dx of −log(bᵢ − aᵢ·x) is +aᵢ/sᵢ, so the barrier's gradient is ~+A.T @ (1/s)~.
The objective part is −t c, because we /minimize/ −t c·x in order to maximize c·x.

** Functional route
numpy expressions are already pure, so the barrier is three expressions over one slack vector ~s = b − Ax~:
the value, the gradient ~−t c + Aᵀ(1/s)~, and the Hessian ~Aᵀ diag(1/s²) A~. Build the Hessian by broadcasting
~(1/s²)[:, None] * A~ rather than forming the diagonal matrix. Return ~(inf, None, None)~ outside the domain.

* Step 2 — Newton centering

** Rung 1
~dx = -np.linalg.solve(H, g)~; ~dec2 = -g @ dx~, which equals g·H⁻¹g ≥ 0. Stop
when ~dec2 / 2 <= tol~.

** Rung 2 — the line search keeps you feasible
~barrier~ returns ~inf~ outside, and ~inf <= anything~ is false, so the halving
loop automatically rejects infeasible trial points. Guard the loop with
~step > 1e-12~ and stop if it runs out. That is floating point, not a bug.

** Functional route
The step sizes are ~takewhile(lambda st: st > 1e-12, toolz.iterate(lambda st: st / 2, 1.0))~,
and the accepted one is ~next((st for st in steps if <sufficient decrease>), None)~.
The Newton loop itself is ~next(s for s in toolz.iterate(step, start) if s.done or s.k >= max_iter)~.

* Step 3 — The central path

** Rung 1
Loop: ~x, _ = newton_center(A, b, c, x, t)~; ~y = 1 / (t * (b - A @ x))~; append
~(t, x, y)~; if ~m / t <= eps~ return the list; else ~t *= mu~. Starting each
centering from the previous centre is what makes it cheap (about 6 Newton steps).

** Functional route
The /t/ values are known in advance. Count them with
~next(k for k, t in enumerate(toolz.iterate(lambda t: t * mu, t0)) if m / t <= eps) + 1~,
then ~list(toolz.take(count, toolz.iterate(next_point, first_point)))~. Using
~iterate~ for the /t/ sequence reproduces the same floating-point values as
repeated ~t *= mu~.

* Step 4 — The ellipsoid method

** Rung 1
~viol = A @ center - b~; ~i = int(np.argmax(viol))~; if ~viol[i] <= 0~ the centre
is feasible. Otherwise cut with ~a = A[i]~: every feasible point satisfies
~a·z ≤ bᵢ < a·center~, so keeping the half ~a·z ≤ a·center~ loses nothing.

** Rung 2
~P @ a~ is used twice. Compute ~g = P @ a / sqrt(a @ P @ a)~ once, and then
~np.outer(g, g)~ for the rank-one update.

** Functional route
~ellipsoid_step~ is two expressions returning a new (centre, P) pair. The method is an unfold over ~(iteration,
centre, P)~: cut on the most violated constraint, and take the first state that is feasible or has hit ~max_iter~
with ~next(s for s in tz.iterate(step, start) if ...)~.

* Step 5 — The bound

** Rung 1
After /k/ steps the volume is at most vol(B_R)·exp(−k/(2(n+1))). A ball of radius
/r/ has volume (r/R)ⁿ vol(B_R). Solve exp(−k/(2(n+1))) < (r/R)ⁿ for /k/:
k > 2(n+1)·n·ln(R/r). Round up with ~math.ceil~.

** Functional route
One expression; the only care is ~math.ceil~ and the natural log.
