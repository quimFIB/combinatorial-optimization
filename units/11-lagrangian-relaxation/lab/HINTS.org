* Step 1 — The 1-tree

** Rung 1 — Prim in O(n²)
Keep ~best[u]~, the cheapest modified edge from the tree to u, and ~link[u]~, its tree end.
Start with ~best[1] = 0~. Repeat n−1 times: take the cheapest vertex v not in the tree and
add it. If ~link[v] != -1~, record the edge. Then lower ~best[u]~ for every u outside the
tree using ~c(v, u)~.

** Rung 2 — vertex 0
Sort vertices 1..n−1 by ~c(0, u)~ and take two. The bound is the total modified weight
minus 2·Σπ, because every tour has every degree 2, so adding π to both ends of each edge
adds exactly 2·Σπ to its length.

** Functional route
Prim is a fold over range(n − 1). The accumulator is ~(tree vertex set, best[u] = (cost to the tree, link),
edges)~. Each step picks the cheapest vertex outside the tree and returns a new ~best~ dict, relaxed through
it. Vertex 0's two cheapest edges are a ~sorted(...)[:2]~, and the degrees are a count over all the edges.

* Step 2 — Subgradient ascent

** Rung 1 — the order of operations
#+begin_example
L, _, g = oracle(mult); history.append(L)
update best (or count a failure; halve lam after `patience` failures)
if |g|² == 0 or lam < 1e-6: stop
t = lam * max(upper - L, 1e-9) / |g|²
mult = mult + t g; project
#+end_example

** Rung 2 — why this step
If ~upper~ were the true maximum L*, the Polyak step t = (L* − L)/|g|² is the one that
guarantees getting closer to the optimal multipliers. λ ∈ (0, 2] scales it. Using an upper
bound in place of L* overshoots, and halving λ corrects for that.

** Rung 3 — the TSP subgradient
Increasing π_v makes edges at v dearer, so v's degree falls. Degree 3 means π_v should rise,
and degree 1 means it should fall. So g_v = deg_v − 2, and a 1-tree with every degree 2
is a tour: g = 0, and the bound is exact.

** Functional route
An unfold over a state dict: multipliers, λ, iterations since the last improvement, the best bound and its
multipliers, and the history. ~step~ calls the oracle once and returns a new dict: halve λ after ~patience~
non-improving steps, stop on a zero subgradient or a tiny λ. ~tz.drop(1, tz.iterate(step, start))~ skips the
initial state, and ~next(...)~ takes the first stopped state or the one at ~iterations~.

* Step 3 — Edge fixing

** Rung 1 — one tree path search per vertex
Build the adjacency of the tree edges not touching 0. From each s, run a DFS that carries
~heaviest[u] = max(heaviest[parent], c(parent, u))~. For t > s with (s, t) not a tree edge,
test ~L + c(s, t) - heaviest[t] > upper + 1e-9~.

** Rung 2 — why that is the cheapest 1-tree with e
Adding e to a spanning tree creates one cycle, the tree path plus e. Removing the heaviest
other edge on that cycle gives the cheapest spanning tree containing e: this is the exchange
property of matroids from unit 13. At vertex 0, forcing e in means dropping the dearer of
the two chosen edges.

** Functional route
The heaviest edge on each tree path is a breadth-first fixpoint per source: the state is ~(known heaviest
edge to each reached vertex, frontier)~, and a spread step extends the frontier by one layer. ~tz.groupby~
over both directions of the tree edges gives the adjacency. The fixed edges are then two set comprehensions,
one for inner edges and one for edges at vertex 0.

* Step 4 — GAP

** Rung 1 — assignment dualised
L(u) = Σ u_j − Σ_i (best knapsack value for agent i with values u_j − c_ij). Only jobs
with a positive value are worth offering. Knapsack returns item indices into the list you
passed, so map them back to job numbers.

** Rung 2 — capacity dualised
Each job independently picks the agent minimising c_ij + λ_i w_ij, then subtract Σ λ_i b_i.
Project λ onto λ ≥ 0 after each step: ~project=lambda v: [max(0, x) for x in v]~.

** Rung 3 — predicting the winner
B's subproblem (for each job, choose one agent) has integral LP vertices, so B's dual
bound equals the LP bound (Geoffrion). A's subproblem is a knapsack, whose LP is not
integral, so A can be strictly better. The test checks both.

** Functional route
Both relaxations are comprehensions with no state. Dualising assignment solves one knapsack per agent (unit
16's, over the jobs with positive profit) and reads the subgradient from the column sums, ~zip(*x)~.
Dualising capacity gives each job its cheapest agent at the priced cost, and the subgradient is each agent's
load minus capacity.

* Step 5 — Repair

** Rung 1
For each job, the agents i with x[i][j] = 1: keep the cheapest, or None. Compute loads from what you
kept. Loop: for each pending job, ~sorted((cost, agent))~ over agents with room. If any
list is empty, return None. Regret = second − first (infinite if there's only one option).
Place the max-regret job on its first option.

** Functional route
An unfold over the partial assignment dict, starting from the Lagrangian solution's jobs (each kept at its
cheapest agent). A step either returns ~None~ (some job has no agent with room) or adds the job with the
largest regret at its best agent. Stop at ~None~ or at a complete assignment. Loads are recomputed from the
dict each step rather than updated in place.
