* Step 1 — Greedy set cover

** Rung 1 — comparing ratios without floats
Set i beats the current best when ~cost[i] / new_i < cost[best] / new_best~. Cross-multiply:
~cost[i] * new_best < cost[best] * new_i~. Strict ~<~ keeps the lowest index on ties. Skip
sets with ~new_i == 0~.

** Rung 2 — the price lemma the tests check
Order a set S's elements by when greedy covered them, last first: e_k, …, e_1. When e_j was
covered, at least j elements of S were still uncovered, so S itself was available at ratio
≤ c_S / j, and greedy paid at most that. Summing gives Σ_{e∈S} price_e ≤ c_S·H_|S|. Apply it
to every set of an optimal cover.

** Rung 3 — the tight instance
~L = math.lcm(*range(1, n + 1))~ makes every ~L // (i + 1)~ exact. With k elements left, the
cheapest singleton, {k−1} at L/k, beats the whole universe at (L+1)/k by a hair. Greedy takes
it every time and pays L(1 + 1/2 + … + 1/n).

** Functional route
A state ~(uncovered, chosen, price)~ and a step that picks
~min(candidates, key=lambda i: (Fraction(c_i, new_i), i))~. ~tz.iterate(step, start)~ produces the
states; take the first with nothing uncovered. Prices are a dict merged per step.

* Step 2 — Packings

** Rung 1 — why a matching bounds vertex cover
Matching edges share no endpoints, so any cover needs a distinct vertex for each one:
OPT ≥ |M|. A /maximal/ matching's endpoints cover everything, since an uncovered edge could
have been added. So cover = 2|M| ≤ 2·OPT.

** Rung 2 — k-center
Keep ~near[v]~, the distance from v to its nearest chosen centre, and update it with
~min(near[v], dist[new][v])~ after each addition. The next centre is
~max(range(n), key=lambda v: (near[v], -v))~. Stop at k centres or when that maximum is 0.

** Rung 3 — the witness
After the loop, the farthest point w is at distance at least r from every centre, and each centre was at
least r from the earlier ones when it was chosen (distances only shrink). So k + 1 points lie
pairwise ≥ r apart. Two of them share an optimal centre, so 2·OPT ≥ r.

** Functional route
The matching is a fold over edges with state ~(matched set, matching tuple)~. For k-center the
state is the tuple of centres. Recompute ~near~ from it in each step (O(nk) is fine) and iterate
until the stopping test.

* Step 3 — Prim and the double tree

** Rung 1 — Prim in O(n²)
Arrays ~best[u]~ (cheapest edge from the tree to u) and ~parent[u]~. Each round, pick the
cheapest vertex not yet in the tree, add edge (parent, v), then relax ~best~ from v.

** Rung 2 — the walk
A preorder of the tree from 0, with children in increasing order, is exactly the shortcut of the
doubled-edge walk. An explicit stack works: push neighbours in /decreasing/ order so the smallest
is popped first, and skip vertices already seen. Each shortcut replaces a path by a single edge,
which the triangle inequality says is no longer. So tour ≤ 2·MST ≤ 2·OPT: removing one edge of
the optimal tour leaves a spanning tree.

** Functional route
~tz.groupby~ the tree edges in both directions for adjacency, then a recursive preorder
~[v] + concat(preorder(w, v) for w in sorted(children))~. ~shortcut~ is ~list(tz.unique(walk))~.

* Step 4 — Christofides

** Rung 1 — Hierholzer
Adjacency lists of ~(neighbour, edge id)~ and a ~used~ array. Keep a stack starting at ~start~.
Look at the top vertex: if it has an unused edge, mark it and push the other end. Otherwise pop
it onto the circuit. Reverse at the end. Pop used entries off the adjacency list as you go to
keep it linear.

** Rung 2 — why the matching costs ≤ OPT/2
Shortcut the optimal tour to visit only the odd vertices (an even number of them). Its
alternate edges form two perfect matchings on them, summing to at most OPT, so the cheaper one
is ≤ OPT/2. The union of tree and matching has all degrees even and is connected, so an Euler
circuit exists. Its length is MST + matching ≤ 3/2·OPT, and shortcutting only helps.

** Functional route
Hierholzer as an unfold over ~(stack tuple, unused frozenset, circuit tuple)~: each step pushes
along an unused edge or pops onto the circuit. Degrees are ~tz.frequencies(concat(edges))~.

* Step 5 — Scheduling

** Rung 1 — list scheduling's 2 − 1/m
Let job j finish last, on machine i. Before j arrived, i was least loaded, so its load was
≤ (Σp − p_j)/m. Then makespan ≤ (Σp − p_j)/m + p_j ≤ OPT + (1 − 1/m)·OPT, using Σp/m ≤ OPT and
p_j ≤ OPT.

** Rung 2 — LPT
~order = sorted(range(n), key=lambda j: -p[j])~ is stable. Run list scheduling on ~[p[j] for j in order]~,
then write each result back to ~machine[order[pos]]~.

** Rung 3 — the tight families
~[1] * (m * (m - 1)) + [m]~: the unit jobs spread evenly to height m − 1, then the long job
lands on top. For LPT, ~[t for t in range(2*m - 1, m, -1) for _ in range(2)] + [m] * 3~. The
pairs and the first two m-jobs fill every machine to 3m − 1, and the third m-job overflows onto one of them. The
optimum pairs (2m−1, m+1) and so on, with the three m's together.

** Functional route
Fold over processing times with state ~(loads tuple, machines tuple)~, rebuilding the loads tuple with one
entry changed. LPT maps back through ~dict(zip(order, machines))~.
