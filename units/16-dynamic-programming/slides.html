16

Dynamic programming over combinatorial structure

Shortest paths in a DAG of states; knapsack and what "pseudo-polynomial" really means; Held–Karp; trees, treewidth and Courcelle; the vocabulary of parameterised complexity.

needs 15~2 h slides + 3 h lablab: uv run co lab 16

Branch-and-bound (unit 07) searches a tree of decisions and prunes with bounds. Dynamic programming searches a DAG of states and prunes by merging. Two partial solutions that reach the same state are interchangeable for the future, so only the better one survives. A DP is exactly as fast as its state space is small. The whole unit is about finding small state spaces in structure: capacities, subsets, subtrees, bags.

Two later units depend on this one. Unit 10's column generation prices columns with the knapsack DP, and unit 22's knapsack FPTAS is the DP run on rounded values.

How to read this deck

Every DP in the unit is shown filled in on a small instance: a knapsack table for 4 items, the Held–Karp subset table for 4 cities, in/out values on a 7-vertex tree, an elimination ordering on a 5-vertex graph, and Buss's kernel on 7 vertices. All numbers were computed with the lab's reference solution. The one proof on the slides ("FPT iff kernel") is stated, with the argument in the notes.

section 1

States

Merge partial solutions that have the same future.

16 · states

DP is a shortest path in a DAG of states

the recipe
  1. A state summarises a partial solution by exactly what the future needs to know.
  2. A transition extends it by one decision, with a cost.
  3. The states and transitions form a DAG. The optimum is a shortest (or longest) path, computed in topological order.

Time = (number of states) × (transitions per state). Correctness = optimal substructure: an optimal path's prefixes are optimal paths to their states.

The last row is why the others matter. Going from paths to (set, endpoint) merges all orderings of the same set.

Bellman named it in the 1950s. By his own account, "dynamic programming" was chosen partly because it sounded impressive and was hard to object to in a funding environment. The ideas are older: shortest paths in DAGs, and backwards induction in sequential decision problems.

The "same future" test is the thing to practise. For knapsack, the future cares how much capacity remains, not which items produced it. For TSP, it cares which cities remain and where you are, not the order you took. When you can't find such a summary, the problem usually has no good DP. That's an informal version of why some problems stay hard under every parameterisation.

Knapsack in $O(nC)$ — and why that is not P = NP

$$B_i(c) = \max\bigl(B_{i-1}(c),\ B_{i-1}(c - w_i) + v_i\bigr)$$

$n$ items, capacity $C$: $O(nC)$ time. Knapsack is NP-hard. So have we shown P = NP?

no: count the input

$C$ is written in $\log_2 C$ bits. $O(nC) = O(n \cdot 2^{\log C})$ is exponential in the input length. It is polynomial only in the numeric value: a pseudo-polynomial algorithm.

weak vs strong NP-hardness

Knapsack is weakly NP-hard: hard only when the numbers are huge. Bin packing and TSP are strongly NP-hard: still hard with numbers bounded by a polynomial in $n$. So they have no pseudo-polynomial algorithm unless P = NP.

The same items at every scale give the same answer. Only the number of digits grew, and the DP paid ×10 per digit. The MIP solver's branch-and-bound doesn't care, because LP bounds are scale-invariant. That's the same contrast as in unit 07, viewed from the other side.

A useful variant, used by unit 22's FPTAS: index by value instead of weight. $W_i(p)$ = least weight achieving value $p$ takes $O(n \cdot \sum v)$. Round values down to multiples of $\varepsilon v_{\max} / n$ and the table shrinks to $O(n^3/\varepsilon)$, while the answer loses at most a factor $1 - \varepsilon$.

The lab's unbounded knapsack variant is unit 10's pricing problem. Given dual prices $\pi_i$ on item demands, find the cutting pattern of maximum total price. A pattern with total price above 1 is a column with negative reduced cost.

section 2

Subsets

From $n!$ to $n^2 2^n$.

16 · subsets

Held–Karp (and Bellman), 1962

$$\begin{aligned} D(\{k\}, k) &= d_{0k} \\ D(S, k) &= \min_{j \in S \setminus \{k\}} D(S \setminus \{k\}, j) + d_{jk} \end{aligned}$$

The Held–Karp DP: $S \subseteq \{1, \dots, n-1\}$, $k \in S$. Tour length $= \min_k D(\text{all}, k) + d_{k0}$.

  • $O(n^2 2^n)$ time and $O(n 2^n)$ space. Space is what stops you around $n = 25$ to $30$.
  • Works unchanged for asymmetric distances.
  • A bitmask per subset; masks in increasing order are topologically sorted, since $S \setminus \{k\} < S$.
sixty years on

No $O((2 - \varepsilon)^n)$ algorithm is known for general weighted TSP. For undirected Hamiltonicity, Björklund (2014) broke $2^n$ with algebraic methods.

Three completely different algorithms, one table. Held–Karp's time is a function of $n$ only: steady, predictable, exponential. Branch-and-bound on MTZ depends on how weak the formulation is, and MTZ is very weak (unit 05's lesson). Lazy DFJ uses the subtour relaxation of unit 09, which is within about 1% on Euclidean instances, so it barely branches. The crossover sits between $n = 14$ and $16$. SCIP on MTZ is erratic (5 s at 18, 0.3 s at 20), because its presolve and cuts sometimes recover a lot of the missing strength and sometimes don't.

The lab's reference vectorises Held–Karp with numpy, one array operation per (subset size, end city). A plain-Python dict version runs 0.24 s at $n = 14$, which is still fine. The point of the table is the slope, not the constant.

Where DP over subsets still wins: small $n$ with complicated side constraints (time windows, precedences) that ruin a MIP formulation but only shrink the DP's state space. It's also the pricing engine of branch-and-price for vehicle routing (unit 10), as a resource-constrained shortest path.

section 3

Treewidth

How far from a tree is this graph?

16 · treewidth

On trees, NP-hard problems become easy

The tree DP for vertex cover, rooted anywhere:

$$\begin{aligned} \mathrm{in}(v) &= w_v + \textstyle\sum_{c} \min(\mathrm{in}(c), \mathrm{out}(c)) \\ \mathrm{out}(v) &= \textstyle\sum_{c} \mathrm{in}(c) \end{aligned}$$

$O(n)$. The state is (vertex, in or out) because a subtree talks to the rest of the tree only through its root.

Lab step 3 runs it on a 5 000-vertex path, so it must not recurse. Python's recursion limit is 1 000.

the separator idea

A tree DP works because removing a vertex splits the tree into independent parts. If a graph splits into independent parts by removing small sets of vertices, recursively, the same DP works with the small set as the state.

"Small" is the treewidth, and the state space is $2^{\text{set size}}$ for vertex cover, or $q^{\text{set size}}$ for $q$-colouring.

The same argument makes independent set, dominating set, colouring and Hamiltonicity linear-time on trees, and FPT in treewidth.

Why reconstruction needs care. The table says only the optimal value. To recover the cover, walk parents before children. A root takes the better of in and out. A child must be in when its parent is out, because the edge between them has to be covered. Otherwise the child takes its better option. A mutation that forgets the "must" produces an invalid cover with a smaller weight, and the tests check coverage separately for exactly that reason.

16 · treewidth

Tree decompositions

Every edge sits in a bag, and the bags holding each vertex are contiguous (5 is in the top three, 2 in the bottom three).

definition (Robertson–Seymour)

A tree decomposition: a tree $T$ with a bag $B_t \subseteq V$ per node, such that

  1. every edge $uv$ lies inside some bag;
  2. for every vertex $v$, the bags containing $v$ form a connected subtree.

Width $= \max |B_t| - 1$. Treewidth $\mathrm{tw}(G)$ = the minimum width over all decompositions.

Trees: 1. Cycles: 2. Series–parallel graphs: $\le 2$. The $k \times k$ grid: $k$. $K_n$: $n - 1$. The lab's $k$-trees: exactly $k$.

Property 2 is what makes a bag a separator: the parts of the graph below and above it share only the bag's vertices.

Why the $-1$: so that trees have width 1. The minus one is a historical convenience. The DP's state space depends on the bag size $w + 1$, which is why the runtime formula has $2^{w+1}$.

Property 2 is the one people forget, and lab step 4's checker must test it on its own. The test hands it the bags $\{0,1\}, \{2,3\}, \{1,2\}$ in a path whose middle is $\{2,3\}$, so vertex 1's bags are not contiguous. A decomposition without property 2 gives a DP that silently counts a vertex's weight twice or assigns it inconsistently.

16 · treewidth

Finding decompositions: elimination orderings

  1. Pick a vertex $v$. Its bag is $v$ plus its current neighbours.
  2. Join those neighbours into a clique (the fill-in), then delete $v$.
  3. Repeat. Hang each bag off the bag of its earliest-eliminated neighbour.
fact

$\mathrm{tw}(G) = \min$ over elimination orderings of the largest neighbourhood at elimination time. Every decomposition comes from some ordering.

Computing treewidth is NP-hard (Arnborg, Corneil & Proskurowski 1987). For fixed $k$, width $\le k$ is decidable in linear time (Bodlaender 1996), with constants too large to run.

in practice: greedy orderings

Min-degree: eliminate the vertex of smallest current degree. Min-fill: the one adding fewest fill edges. Min-fill is exact on chordal graphs (a simplicial vertex adds no fill); both are exact on $k$-trees; both are often close elsewhere.

orderings matter enormously

A star eliminated centre-first turns the leaves into a clique, giving width $n - 1$. Leaves first gives width 1. Lab step 4 tests both.

networkx ships both heuristics (treewidth_min_degree, treewidth_min_fill_in). Exact solvers from the PACE 2016–17 challenges handle graphs of hundreds of vertices.

Why the bag of $v$ can hang off its earliest-eliminated later neighbour $u$: when $u$ is eliminated, all of $v$'s other remaining neighbours are still present and, thanks to the fill-in, adjacent to $u$. So they're all in $u$'s bag. That gives property 2 along the chain of attachments.

The same fill-in is what sparse Cholesky factorisation creates, and the same orderings (minimum degree, nested dissection) are used there. It's the reason unit 04's interior-point methods care about orderings. Treewidth and sparse linear algebra are two views of one combinatorial object, chordal completions.

DP over a decomposition — and predicting its runtime

The DP over a decomposition. Root it. For each bag $t$ and each $S \subseteq B_t$ covering the edges inside $B_t$:

$$\begin{aligned} T_t(S) &= w(S) + \textstyle\sum_{c\ \text{child}} \beta_c(S \cap B_c) \\ \beta_c(P) &= \min_{S' \subseteq B_c,\ S' \cap B_t = P} T_c(S') - w(P) \end{aligned}$$

Group each child's table by its restriction to the shared vertices once, then each parent entry costs $O(1)$ per child. Total $\approx \sum_t 2^{|B_t|}$, times small factors.

Every restriction has some valid child entry: put all non-shared vertices in the cover.

The subtraction of $w(S' \cap B_t)$ is the whole trick of combining children. A vertex in both the child bag and the parent bag is counted in the parent's $w(S)$. By property 2, any vertex shared by two children is also in the parent, so it is subtracted from each child and counted exactly once.

Textbooks convert to a nice decomposition (introduce, forget and join nodes, each changing one vertex), which makes the $O(2^w \cdot n)$ bound clean and the proofs uniform. The lab skips that. Grouping by restriction gives the same asymptotics with less code.

The HiGHS column is the caveat to "FPT is fast". These graphs are easy for LP-based search whatever their width, because the vertex cover LP is half-integral and nearly tight on sparse graphs. A DP exponential in the width is the right tool when the width is genuinely small and the problem is hard for relaxations: counting, many global constraints, or problems without a good LP.

16 · treewidth

Courcelle's theorem: why all of these work

Courcelle 1990

Every graph property expressible in monadic second-order logic (MSO₂: quantify over vertices, edges, and sets of them) can be decided in time $f(k, |\varphi|) \cdot n$ on graphs of treewidth $\le k$.

Arnborg, Lagergren & Seese (1991) extended it to optimisation: find a minimum or maximum set satisfying an MSO formula.

Vertex cover in MSO:

$$\exists S\ \forall u\,\forall v\ \bigl(\mathrm{adj}(u,v) \rightarrow u \in S \lor v \in S\bigr)$$

3-colourability, Hamiltonicity, connectivity and dominating set are all expressible too, so all are linear-time for bounded treewidth.

the catch

$f$ is a tower of exponentials whose height grows with the formula's quantifier alternation. Courcelle tells you a DP exists. You still write the $2^w$ one by hand.

The proof compiles the formula into a finite tree automaton that runs over the decomposition. Its states are exactly the "subset of the bag" states of a hand-written DP, generalised. The tower-of-exponentials blow-up is unavoidable in general: Frick and Grohe (2004) showed that, unless P = NP, no elementary $f$ works for MSO on trees.

Why this is the right "general statement": it explains in one theorem why the lab's three DPs all follow the same shape. Each problem is definable in MSO, and each DP is a hand-optimised version of the automaton.

16 · parameters

FPT, XP, and kernels

with a parameter
  • FPT: time $f(k) \cdot n^{O(1)}$, with the exponential confined to $k$. Vertex cover by solution size: $O(1.2738^k + kn)$ (Chen, Kanj & Xia 2010). Anything MSO by treewidth.
  • XP: time $n^{f(k)}$, polynomial for each fixed $k$ but with $k$ in the exponent. $k$-clique by brute force is $O(n^k)$.
  • W[1]-hard: believed not FPT. $k$-clique, $k$-independent set.
kernelisation

A polynomial-time reduction to an equivalent instance of size $g(k)$. A decidable problem is FPT iff it has a kernel.

why: notes (N)

Buss's kernel for vertex cover $\le k$: a vertex of degree $> k$ must be in the cover, so take it and set $k \leftarrow k - 1$. Once none remain, more than $k^2$ edges means "no". Result: $O(k^2)$ edges. The LP (unit 24's half-integrality) gives a $2k$-vertex kernel.

Kernels are exactly what presolve does in a MIP solver (unit 27), with a guarantee.

Why this vocabulary is honest. "NP-hard" says only that the worst case over all inputs is bad. Parameterised complexity asks which aspect of the input the hardness lives in. Knapsack's lives in the magnitude of the numbers (pseudo-polynomial). Vertex cover's lives in the solution size and in the treewidth, and not in $n$. Clique's apparently doesn't live in the solution size, since it is W[1]-hard.

Full proof

The "FPT iff kernel" proof is short. Given an $f(k) n^c$ algorithm: if $n \ge f(k)$, run it, which takes $n^{c+1}$ time, polynomial, and output a trivial yes or no instance. Otherwise the instance itself has size $< f(k)$, and it is its own kernel. Hence the interest in polynomial kernels, which not every FPT problem has under standard assumptions.

Kernel: the path $1\!-\!5\!-\!6$, asking for a cover of size $\le 2$.

why vertex 0 is forced

If 0 were left out, all 4 of its neighbours would have to be in, and $4 > 3 = k$. So any cover of size $\le 3$ contains 0.

solving the kernel

$\{5\}$ covers the path. Put back the forced vertex: cover $\{0, 5\}$, size 2 $\le 3$. Yes.

The kernel's size depends only on $k$ (at most $k^2$ edges), however many leaves the star had.

The "more than $k^2$ edges means no" rule: once every vertex has degree $\le k$, each cover vertex covers at most $k$ edges, so $k$ of them cover at most $k^2$. Here there are 2 edges and $k = 2$ after the reduction, so the rule doesn't fire.

Add 10 more leaves to vertex 0 and the kernel is identical: that is the point of a kernel. The reference tree_vertex_cover (this graph is a tree) confirms the minimum cover is $\{0, 5\}$.
