Automatic differentiation

Dual numbers and forward mode, the tape and reverse mode, why a full gradient costs one backward pass, what it costs in memory, and where the answers quietly stop being derivatives.

needs 29, 28~1½ h slides + 2½ h lablab: uv run co lab 30

Unit 29 assumed gradients were given. This unit builds the machine that produces them for any program. The one fact that explains modern machine learning's existence is in section 2: reverse mode computes a full gradient in a constant number of passes, regardless of the number of parameters.

How to read this deck

One function, $f(x, y) = xy + \sin x$ at $(1, 2)$, runs through sections 1–3: forward mode with dual numbers, the tape and its adjoint table, a VJP and a Hessian-vector product, all computed with the lab's reference engines. The MLP's tape memory is then counted by hand, array by array.

section 1

Three kinds of derivative

Only one of them is exact and cheap.

30 · kinds

Symbolic, numerical, automatic

methodwhat it doesfailure mode
symbolicrewrites the formulaexpression swell; no loops or branches
numerical$\frac{f(x+h) - f(x-h)}{2h}$truncation error $O(h^2)$ against rounding error $O(\epsilon/h)$; one evaluation pair per input
automaticchain rule on the operations the program executeddifferentiates the program, not the function (section 4)

Numerical derivatives are the test oracle: every op in the lab is gradient-checked against central differences.

forward mode: dual numbers $$\begin{aligned}(a + b\varepsilon)(c + d\varepsilon) &= ac + (ad + bc)\varepsilon \\ g(a + b\varepsilon) &= g(a) + g'(a)\, b\,\varepsilon\end{aligned}$$

with $\varepsilon^2 = 0$.

Seed $x = x_0 + 1\varepsilon$, run the program, read $f'(x_0)$ off the $\varepsilon$ part. For $f: \mathbb{R}^n \to \mathbb{R}$, one pass per input direction: n passes for a gradient.

Lab step 1: twelve operators and five functions. The same code also accepts a Dual whose value is a Dual.

The finite-difference trade-off: with h too large the Taylor remainder dominates, and with h too small the subtraction f(x+h) − f(x−h) loses digits to rounding. For central differences in double precision the sweet spot is around h ≈ 1e−5 to 1e−6, giving about 10 correct digits. The lab tests use exactly that, and compare to 1e−4 or 1e−6 relative tolerance.

Expression swell: the symbolic derivative of a product of n factors has n terms, each with n − 1 factors. Automatic differentiation keeps the intermediate values instead of expanding the formula, which is why its cost stays proportional to the program's.

The product rule for dual numbers, $(a + b\varepsilon)(c + d\varepsilon) = ac + (ad + bc)\varepsilon$, is the product rule of calculus: in pass 1, $a = 1, b = 1, c = 2, d = 0$ gives $\varepsilon$ part 2. The function rule $g(a + b\varepsilon) = g(a) + g'(a) b \varepsilon$ gives $\sin(1 + \varepsilon) = 0.8415 + 0.5403\varepsilon$.

Both passes are the reference Dual class: f(Dual(1, 1), Dual(2, 0)) has derivative 2.5403023 and f(1, Dual(2, 1)) has derivative 1.0.

section 2

Reverse mode

The whole gradient in one backward pass.

30 · reverse

The Wengert tape

Record every operation with its inputs and local derivatives (the tape). Then sweep backwards (the backward pass), with adjoints $\bar v = \partial f / \partial v$:

$$\bar u \mathrel{+}= \bar v \cdot \frac{\partial v}{\partial u}$$

for each edge $u \to v$, visiting nodes in reverse topological order.

why reverse is cheap

Each operation's backward step costs a small constant times its forward step. So a full gradient costs a constant multiple of one function evaluation, whatever the number of inputs: the cheap gradient principle (Griewank), with a constant of about 4 to 5.

Wengert (1964) for the recorded list; Linnainmaa (1970) for reverse accumulation; backpropagation (Rumelhart, Hinton & Williams 1986) is reverse mode on a network.

Lab then, gradient of $\sum_i \sin(x_i)\, x_{i+1}$:

nforward (n passes)reverse (1 sweep)jax.grad, jit
100.000 s0.0001 s0.0002 s
1000.014 s0.0007 s0.0004 s
1 0001.55 s0.0057 s0.0021 s

Forward mode grows like $n^2$, reverse like $n$. At a million parameters, forward mode is a million passes and reverse mode is one.

two traps in the sweep

Each node once: a graph with $2^{30}$ paths but 33 nodes must take 33 steps. No recursion: a 20 000-deep graph overflows Python's stack. Lab step 2 tests both.

For f: Rⁿ → Rᵐ, forward mode computes one Jacobian column per pass (a JVP) and reverse mode one row per pass (a VJP). So forward mode wins when m ≫ n, as for a function of one parameter with many outputs, and reverse mode wins when n ≫ m, which is every loss function.

Why the jit column is faster than the lab's reverse mode at n = 1 000: the lab's scalar tape allocates a Python object per operation. JAX traces the program once into array operations. The asymptotics are the same; the constant differs by Python's per-object overhead.

explore interactively

Order matters. $v_0$'s adjoint is only complete after every node that uses $v_0$ has been visited, which is what reverse topological order guarantees: $v_4$, then $v_3$ and $v_2$, then the inputs. Visiting $v_0$ before $v_3$ would propagate a half-finished adjoint.

The reference reverse_gradient on this function returns value 2.8414710 and gradient $[2.5403023, 1.0]$, matching the forward passes to all printed digits.

section 3

Memory and higher order

The tape is the price.

30 · memory

What the tape holds, and checkpointing

Reverse mode must keep every intermediate its backward steps need until the sweep reaches them: the tape memory, mostly activations. For the lab's MLP, the distinct arrays are:

  • the input batch: batch × in
  • per layer: W (m × n), matmul output and bias-add output (batch × n each)
  • per hidden layer: the tanh output (batch × n), which its vjp reuses
  • the loss's difference array (batch × out), and the scalar loss

MLP [2, 64, 64, 1], batch 64: predicted 233 480 bytes, measured 233 480 bytes. The count is on the next slide.

checkpointing

Keep only some intermediates and recompute the rest during the backward sweep. Keeping every $\sqrt{L}$-th layer of an $L$-layer chain costs $O(\sqrt L)$ memory and about one extra forward pass (Chen et al. 2016). Griewank's revolve gets $O(\log L)$ memory for $O(\log L)$ times the compute, which is optimal for chains.

why memory, not time, is the limit

Activation memory grows with batch × width × depth and must coexist on the device. Parameters are a fixed cost. That's why large-model training is designed around the tape.

What isn't on the tape matters as much. The biases aren't: add_bias's vjp needs only the incoming gradient. The matmul's saved input for layers after the first is the previous tanh output, which is already counted. Counting by array identity rather than by operation is what makes the prediction exact.

In-place mutation is the classic way to break a tape: if an array saved for backward is modified during the forward pass, the vjp silently uses the wrong values. PyTorch tracks version counters on tensors to detect exactly this, and JAX forbids mutation of traced arrays.

At 8 bytes per float64: $29\,185 \times 8 = \mathbf{233\,480}$ bytes, exactly what the lab measures for the MLP.

what the count tells you

The 64×64 arrays dominate: 7 of them hold 28 672 of the 29 185 numbers. Double the batch and the six activations among them double; the weights don't.

The last layer's output is not followed by tanh (a regression output), and the biases are not saved at all, since adding a bias needs no stored value to differentiate.

The rule the lab uses is to count each distinct array once. The matmul in layer 2 needs its input, but that input is layer 1's tanh output, already in the table. Counting by operation instead would double-count it and overshoot.

The seven 64×64-sized arrays: layer 1's three batch arrays, and layer 2's weight matrix plus its three batch arrays. $7 \times 4\,096 = 28\,672$.

on the example

$H = \begin{pmatrix} -\sin x & 1 \\ 1 & 0 \end{pmatrix}$ at $(1, 2)$. With $v = (1, 0)$: $Hv = (-0.8415,\ 1)$, one tape run on dual inputs $(1 + \varepsilon,\ 2)$.

forward over reverse in the lab

Write the reverse-mode tape so its values can be dual numbers. Seed inputs $x_i + v_i\varepsilon$, sweep backwards, and the $\varepsilon$ parts of the gradient are $Hv$. One forward and one backward pass: no Hessian is ever formed.

HVPs are what Newton-CG and truncated-Newton methods use, and what "is this point a saddle?" needs, at the cost of about two gradients.

Agreement to machine precision is the expected result when both implementations apply the same chain rule to the same operations in double precision. A difference of 1e−8 would indicate a bug or a different operation (for example a fused kernel), not "numerical noise".

The dual-number trick generalises: nesting dual numbers gives higher derivatives (hyper-dual numbers), and forward-over-reverse is the standard composition in JAX (jax.jvp of jax.grad).

A VJP on the example. For $(x, y) \mapsto (xy,\ \sin x)$ and $u = (2, -1)$, one backward sweep seeded with $u$ gives $u^\top J = (2y - \cos x,\ 2x) = (3.4597,\ 2)$.

The example box. The reference hvp with inputs $(1, 2)$ and direction $(1, 0)$ returns $[-0.8414710, 1.0]$: the first column of $H$. The VJP: $J$ has rows $(y, x)$ and $(\cos x, 0)$, so $u^\top J = 2(2, 1) - (0.5403, 0) = (3.4597, 2)$.

An MLP on terrain elevations

matplotlib's sample elevation model of the Jacksboro fault region: 344 × 403 heights, standard deviation 162.5 m. Learn elevation from grid coordinates: MLP 2 → 64 → 64 → 1, tanh, batch 64, 60 epochs of SGD. Train on 6 000 points, test on 6 000 others.

  • It learns: 90 m against 145 m for a plane, on data it didn't train on (train RMSE 88.6 m).
  • Identical to JAX: same initial weights and batch order give the same test error, as they should when the gradients agree to 1e−16.
  • JAX was slower at this size. With 64-unit layers, per-step overhead plausibly outweighs compilation. That's a statement about this size, not about JAX.

The dataset choice: sklearn isn't installed and downloads need permission, so the lab uses real data already shipped with matplotlib.

90 m of error on a 160 m spread is modest. The terrain has ridges and valleys at scales a 64-unit tanh network trained for 60 epochs can't represent. Coordinate networks with Fourier features, or simply more epochs and width, do much better. The point of the exercise is the engine, and the baselines keep the claim honest: the network does beat a plane by a wide margin.

Where autodiff quietly lies

expressionJAX's gradienttruth
jnp.maximum(x, 0) at 00.5undefined (one-sided 0 and 1)
jax.nn.relu at 00.0same function, other convention
jnp.abs at 01.0undefined (one-sided −1, 1)
sqrt(x²) at 0nanundefined; 0 · ∞ in the chain rule
where(x != 1, x, 1.0) at 10.0the identity: 1
argmax([x, 0.5]) at 0.20.00 a.e., a jump at 0.5
the rule: differentiate the program

Autodiff differentiates the program that ran, branch by branch. Where the program branches on a value, or uses a function at a kink, the result is a convention, not a derivative.

  • Non-smooth points: a subgradient if you're lucky, a library convention otherwise.
  • Control flow: the derivative of the branch taken, blind to the other branch.
  • In-place mutation: saved values overwritten before backward.
  • argmax, sorting, rounding: derivatives exist and are zero almost everywhere, which is useless for learning.

The last bullet is the bridge to unit 31. Every discrete decision in this course (a branching variable, a matching, a tour) is an argmax. Its derivative is zero almost everywhere and undefined at the switching points. Unit 31 asks what to do about that: relax the discrete choice (Sinkhorn, Gumbel-softmax), estimate gradients another way (straight-through, REINFORCE), or differentiate the optimality conditions of a continuous relaxation (the implicit function theorem on KKT).
